# 日语 Anki 日常链路 ① · 每日讲义（今天学习生词 → 讲义）

本技能覆盖**一件事**：每天早上学今天这批生词**之前**，把 tag `今天学习生词` 里的词变成一份日语讲义。

选词不在这里：`jp-anki-today-new`（`code\tools\today_new_words.py`）从当天字幕/文字里挑 N 个词、打 tag、全量替换。**本技能只认这个 tag；没有 tag 就不生成。**

## 一、环境与命令

```powershell
$WS  = "<工作区根>"
$PY  = "python"
$EXE = "$WS\code\execution"
```

### 1.1 主流程

```powershell
# 0) 选词（另一条日常任务，不在本技能里）
#    & $PY "$WS\code\tools\today_new_words.py" "字幕.srt" --n 30 --commit

# 只看库存（可选，先确认今天有词）：tag 在各词汇卡组命中多少条
& $PY "$EXE\today_new.py" stats

# 探本地端点：api key / 模型名 / ctx（可选）
& $PY "$EXE\today_new.py" models

# 按 tag 取词 + 预取 JMdict（事实挂到每张词汇卡）→ cards_*.json + split_*.json
& $PY "$EXE\today_new.py" plan

# 复核词典（默认复用 plan 的预取结果，不查库；--refresh-dict 才重查）
& $PY "$EXE\today_new.py" check

# 直连 /v1/responses → 闸门 → 讲义（默认 --per-batch 1；只读词典事实，不再查词典）
& $PY "$EXE\today_new.py" gen

# 产出：
#   output\daily\lessons\cards\NN_out.json（每请求一个，断点续跑单位）
#   output\daily\lessons\cards\NN_in.json（实际发出的卡；含 dict，可单独交接）
#   output\daily\lessons\dict_<日期>.json（词典预取结果：词形/读音/词性 + facts + meta）
#   output\daily\lessons\metrics_<日期>.json（token 账本）
#   output\daily\lesson_latest.md（给用户读的讲义）
```

**今天没有 tag 就到此为止**：`plan` 打印「今天没有 tag:「今天学习生词」的词 → 不生成讲义」，落一份空清单后退出 0；`gen` / `merge` / `check` 看到空清单也直接跳过（退出 0，不调模型、不写讲义）。不要自己拿新卡队列去补。

**隔天保护**：`gen` / `merge` / `check` 默认只认**今天**的 `cards_latest.json`；如果那份清单是昨天的，会直接报错退出（提示先跑 `plan`，或显式 `--date <旧日期>`），不会把昨天的词重讲一遍。

**tag 换批保护**：`gen` 开跑前会核对清单里的词是否还带着 tag「今天学习生词」——选完词之后又换批/清空了（中途再跑一次 `today-new`），就拒绝拿旧清单生成；确要照旧清单跑就加 `--allow-stale-tag`。

### 1.2 关键原则

- **这里不派子代理。** 规范作为 **instructions** 发一次、卡数据作为 `input`，直连 `/v1/responses`（OpenAI Responses API）；默认每个请求 1 张卡（`--per-batch` 可调大，但端点**不复用 KV cache**，调大只是少发几遍前缀，单次输出更长、更容易截断）。
- **断了就直接重跑 `gen`**（卡集对得上的请求自动跳过）；只重来某几张：`gen --only-words "あまり" --restart`；只合并现有产出：`merge`。
- **闸门与重试都是脚本自己的事**，报在 stderr 也不用干预：闸门在 `merge`（逐张覆盖 + `teach` 非空 + date 一致 + 无占位符），不过就**不写讲义**并点名缺哪几张卡的 noteId；模型侧非法 JSON / 漏卡 / 被截断会带提示重问，端点 5xx/429 指数退避（401/403/404 直接报错）。
- **闸门分两层**：`merge` 前拦的是**硬错**（逐张覆盖 / date / 占位符 / 词形不在正文）；
  内容层的毛病（读音对不上、讲解机械错）**不拦讲义**，
  只在正文里就地打 `⚠️`、并在 stderr 末尾集中报一次。讲义要出，但**报告必须转述**。
- **JMdict 词典层（2026-10-25 起：一次预取，之后不查库）**：`plan` 用 `jmdict-lookup`
  那把词典**查一遍**——核验读音/词性/他动自动，并把义项、语域、适用限制整理成事实，
  挂到每张词汇卡的 `dict` 字段（随卡进模型输入、进 `NN_in.json`），明细落 `dict_<日期>.json`。
  `gen` / `merge` / `apply` **只读这份结果，不再打开词典库**；stderr 会打印
  `📖 词典：复用 …（未查库）`。缓存按「日期 + 卡片指纹 + 词典版本 + 缓存版本」校验，
  任一项不符才自动重查一次（`--refresh-dict` 强制重查）。**单条词条才自动改词性**；
  同形多词条（`もん` 同时是者/物/門）只提示，不擅改，句末助词由渲染器的硬编码兜底。
  词形查不到只算「提示」。本层只读词典、不写 Anki；词典不可用时整层跳过，绝不挡住讲义；
  `--no-dict` 可关。
- **渲染器会自动收拾的（别手工改讲义，下次 merge 会覆盖）**：计数口径、同词形平/片假名合并、
  词性统一/校正（词典优先，硬编码兜底）、读音对不上的隐藏。要改内容就改卡片或 `NN_out.json`。
- 最常出问题的一条：**例句必须用上目标词**（本地 27B 常犯），另外「中文翻译语义重复
  （大约…左右）」「拿目标词自比（比『想像』更常用）」「句子没写完」也会触发重问；
  最终仍不合格只**报告**，不拦讲义。
- **取词口径不要自己另算**：全库 tag `今天学习生词` 就是今天的全部词——不按 `is:new`、
  不按 `new.perDay`、不按 `card.due` 再筛一遍。顺序见 §1.3。
- **只读 Anki**：这条链路从不写库（tag 是 `jp-anki-today-new` 写的），退路就是删 `output\daily\` 里的文件重跑。

### 1.3 取词口径（tag + 选词顺序）

三个词汇卡组各查一次笔记（`code\execution\today_new.py::query_for`）：

```
deck:"0-日本语学习::0-词汇::2-考级词汇"      note:"eggrolls-JLPT10k-v3.5" tag:"今天学习生词" -is:suspended
deck:"0-日本语学习::0-词汇::1-高频日语单词 6000" note:"Japanese Vocabulary"   tag:"今天学习生词" -is:suspended
deck:"0-日本语学习::0-词汇::0-素材生词"       note:"Japanese Vocabulary"   tag:"今天学习生词" -is:suspended
```

- **一个笔记 = 一条讲义条目**。这三个词汇模型的笔记都只有 1 张卡，所以「张卡」＝「笔记」。
  不截断、不满额补位：tag 里有 30 个就是 30 个，`stats` 的合计数应当等于 `plan` 的合计。
- **顺序**：读当天 `data\daily_new\<日期>\picked.json` 里 `picked[]` 的顺序（= `JitenAnimeRank` 升序，
  也就是 `jp-anki-today-new` 的选词顺序）；没有这份记录（手动打的 tag）时按「级别 → 牌组 → 词形」兜底。
- **牌组只用来标级别**：词可能被临时收进筛选牌组（如 `4-今天词汇`），Anki 的 `deck:` 搜索仍按原卡组命中；
  讲义按 `noteId` 取字段，不受当前所在牌组影响。
- **语法 / 例句单元已移出每日讲义**（2026-10-28 简化）：它们没有对应的「今天学哪些」清单。
  渲染层仍保留旧版分支，`merge --date <旧日期>` 还能渲染当时带语法/例句的 manifest；
  新跑出来的讲义只有词汇一节。
- 想换一批词 / 清空今天的词：走 `jp-anki-today-new`（`--clear --commit` / `--revert --commit`），
  然后重跑 `plan`。不要手改讲义或手删 tag。

教学规范本体是 `code\execution\lesson_local_prompt.md`（要改模型的教学口径就改它，**你不用主动读**）。

## 二、跑完必须验收（2026-10-28 按「只讲 tag」更新）

讲义生成完**不要直接说「完成了」**。按顺序过一遍，每条都有明确的返工动作：

| # | 看什么 | 不合格怎么办 |
|---|---|---|
| 1 | 开头两个数对得上：`共 N 张卡｜M 条讲解（词汇 M 条）`，与「今日一览」的行数、来源表合计一致；且 `N = stats` 的 tag 命中数 | 脚本算的，对不上就是回归——跑 `code\tests\test_lesson_render.py` |
| 2 | 「本讲义 N 条讲解 = 词汇 N 条」与来源表三个卡组的「今日取词」之和一致；来源列写着 `tag:「今天学习生词」` | 同上；若看到「上限」列 = 渲染的是旧 manifest，重跑 `plan` |
| 3 | 每个词条的读音不是 `—`；出现 `⚠️ 卡片读音字段…` 就是卡片脏 | 记下来报给用户；别改脚本、别手改讲义 |
| 4 | 词性全是中文体系（`他动词1类`/`名词`/`感叹词`/`终助词`），没有 `Verb`/`Noun` | 出现「词性说明」段 = 卡片字段要回改，转述给用户 |
| 5 | 例句读一遍：有没有「大约…左右」、拿同一个词自比、半句话、明显不像日语的说法 | `gen --only-words "<那个词>" --restart` |
| 6 | stderr 末尾的 `⚠️ 讲义里有 N 条内容问题` | **逐条转述**（这是唯一会漏看的地方），并给出第 5 条的返工命令 |
| 7 | stderr 的 `📖 词典：复用 …（未查库）` 或 `已预取 N 张词汇卡（原因）`；以及 `📖 JMdict 核验：… 硬错 / 建议 / 提示`（`check` 同样输出） | **逐条转述**：复用＝正常（没第二次查库）；重查＝缓存失效原因写清楚了。硬错＝读音/词形要回 Anki 改；建议＝词性已按词典校正，回改 `Part of Speech`；提示＝查不到/同形多词条，不一定是错 |
| 8 | 讲义里**不该**出现 `## 语法` / `## 例句卡` 节 | 出现说明在渲染旧版 manifest（`--date` 指错了），重跑 `plan` |

复审点名的硬毛病，脚本现在**机械拦/标注**（`today_new.py`，回归测试 `test_lesson_render.py`）：

- 词形与读音对不上（`こ` / `あそこ`）→ 读音显示 `—` + 就地警告；
- 同词重复（`うっ` / `ウッ`、`あー` / `アー`）→ 合并一条，表记变体列在旁边；
- 词性标错（`ん`/`もん`＝终助词，`あっ`/`え`/`うっ`/`んっ`/`あー`/`よし`＝感叹词）→ 统一中文体系并校正；
- 计数口径不一致 → 开头、各节小标题、来源表全部从同一份分组派生；
- 讲解机械错（语义重复 / 自指比较 / 没写完 / 例句没用上目标词）→ `gen` 重问，`merge` 集中报。

**词典层（2026-10-24 新增，2026-10-25 改为「一次预取」）**：
`code\common\jmdict_check.py` 直连 `jmdict-lookup` 那把 JMdict
（`data\dict\jmdictpy\jmdict.db`），在**调模型之前**查一次：核验词形/读音/词性，
同时产出义项/语域/适用限制事实，挂到每张词汇卡的 `dict` 字段。回归测试 `test_lesson_dict.py`：

- 读音不在词典读音表 → **硬错**，报候选读音；若读音本身是另一个词条（`あそこ`＝彼処），
  直接点出「词形可能取错」——`こ`/`あそこ` 这类挖错的卡不用人再猜；
- 词性与词典冲突 → **建议**；单条词条才自动改（`あっ`→感叹词），同形多词条只提示；
- 他动词/自动词标反 → **建议**；
- 词形查不到 / 同形多词条 → **提示**，不判错；
- **事实随卡进模型输入**（`senses[].glosses` / `tags` / `applies`），模型按词典定读音与义项；
  `gen` / `merge` / `apply` 只读 `dict_<日期>.json`，**不再打开词典库**（`--refresh-dict` 才重查）。

**词典能证伪的只有「词形-读音-词性」这三样**：释义对不对、多义词取哪条、例句自不自然，
仍由模型结合卡片自带例句判断（现在有词典义项可依，但规范层面的约束不变）。

**提示词层面（机械只能抓一部分，规范本体是 `code\execution\lesson_local_prompt.md`
的「内容铁律」，别删）**：自指比较（`比「X」更常用` 能机械抓，别种说法抓不到）、
同音异义混讲（`ひく`＝引く/轢く/惹く、`あう`＝会う/合う/遭う）、搭配不自然
（`タイミングを見逃す`、`舌先で味をなめる`、`良いチャンスを逃がすな`）、
`得る` 的否定/可能用法（`合格はあり得ない`）、释义漏掉最常用义项、例句不像日本人说的话。

## 三、已知卡片脏数据（脚本只标注，不改库）

| 现象 | 根因 | 处理 |
|---|---|---|
| 词形 `こ`、读音 `あそこ`、释义「那里；远处」 | 素材生词挖词时词形取错 | 回 Anki 改 `Word`/`Transliteration`；讲义已隐藏读音并标注；`check` 报**硬错**并指出「あそこ＝彼処」 |
| `ん`/`もん` 标「副词／惯用句」，`あっ`/`あー` 标「副词」 | 卡片 `Part of Speech` 字段错 | 讲义按终助词/感叹词显示；`check` 里词典能定的（`あっ`/`うっ`/`んっ`/`あー`）标**建议**，`ん`/`もん`/`え` 词典收不全，只给**提示** |
| 同形多词条：`もん`＝者/物/門，`え`＝絵/餌/江… | 假名词挖词时只取了一个表记 | 词典层只提示「同形多词条，不自动改」，避免把句末助词改成名词；讲解有没有混讲由人判断 |
| `うっ`/`ウッ`、`あー`/`アー` 各两张卡 | 素材里平/片假名各建了一张 | 讲义合并成一条；要不要 suspend 重复卡由用户决定（本技能不动调度） |

## 四、收工汇报

- 今天 tag 里有几个词、`plan` 是否落盘、`gen` 是否走完、闸门有没有点名缺卡
  （没有 tag 就直说「今天没有选词，未生成」，不要补跑别的口径）；
- **stderr 的质量报告（N 条）逐条转述**，并说明哪些是讲解问题（可 `--restart` 重来）、
  哪些是卡片数据问题（要回 Anki 改）；
- **`📖 词典：复用/已预取` + `📖 JMdict 核验` 的数字与明细照抄**
  （硬错 / 建议 / 提示各几条、点名的词；说清这次是复用预取还是缓存失效重查），
  并说明讲义里已按词典校正了哪些词性、隐藏了哪条读音；
- 讲义路径（`output\daily\lesson_latest.md`）、词典预取明细（`output\daily\lessons\dict_<日期>.json`）、
  token 账本路径（`output\daily\lessons\metrics_<日期>.json`）。
