# 日语 Anki · 今天学习生词（每天按本作暴露挑 30 个词）

本技能覆盖**一件事**：给一集字幕或一整部作品的字幕目录，从**已有词库**里挑出 30 个
今天最值得学、而且你还没学过的词，给它们打上 `今天学习生词` 标签；旧的同标签先摘掉，
所以这个标签永远只代表「今天这一批」。

> **默认只筛一集**（2026-11-01 口径）：给一集字幕就**只读这一集**，不扫同目录其它集——
> 「今天的词」只来自今天看的这集。要整季必须显式：给**目录**，或对单集加 `--season`。
> 单集模式下 `跨集数` 恒为 1，次数项/集数项只在公式兜底时有意义；排序本来就看模型。
>
> **排序以模型为主，公式兜底**：Sudachi 只负责「不漏词、词形对得上」，
> 「这个词值不值得学」由本地模型**一集一次**读完本集台词后排序；公式只在模型不可用时定序。
>
> 本技能**只打标签**。标签不是排期：它不会把这 N 个词挪到新卡队首；要改学习顺序请另加载 `jp-anki-activate`。

## 一、边界（不可越线）

| 允许 | 不允许 |
|---|---|
| 加 / 摘 **一个** 标签 `今天学习生词` | 写 `due` / `ivl` / `factor` / `type` / `queue` / `reps` / `lapses` |
| 读三个词汇卡组、读全库 `tag:"今天学习生词"` | 改任何字段（`Word` / `JitenAnimeRank` / `AINote` …）、改 deck |
| 写 `data/daily_new/` 与 `output/daily/today_new_words.md` | 建卡、删卡、配音、动 `3-专有词汇` |
| 回退时恢复上一次运行前的标签集合 | 加日期标签、加 `::` 前缀、顺手排期 |

- **「没学过」按笔记判断**：同一词形下，已学的那张笔记排除，**别的未学笔记照选照标**。
  听辨卡和看字辨意卡服务不同功能，本来就该各有一张。
- **一个词打名下所有未学笔记**：名额按**词**算（30 个词），所以最终标签数可能多于 30。
- **JAR 门槛 1–30000**：无排名（空 / 0 / 999999）与 JAR >30000 的词**不进今天的名单**，
  但会登记到 `data/daily_new/unranked.json`（待建卡清单），`doctor` 每天用提示报数量 + 前 5 个；
  之后补了 JAR 的词下次运行自动出清。**不建卡**——建卡是用户的事。
- **名额 = N 个内容词 + `--particles` 个助词/感动词**（默认 2）：语气词不占内容词名额。
- **不去重**：复合词各自独立（`魔神` / `魔神族` 都算候选），同词多写法也不合并。
- **已带 `复习::*` 的词仍可入选**：今天学习集与字幕复习集互相独立。
- **全量替换**：同一天换材料再跑，以最后一次结果为准；旧标签里今天没选中的会被摘掉。
- **0 个候选时不改库**：保留旧标签并退出码 2，先检查输入/是否全学完，不要默认清空。

## 二、命令（先把两个变量设好）

```powershell
$WS = "<工作区根>"
$PY = "python"
$PICK = "$WS\code\tools\today_new_words.py"
```

> 开工前先过强制门禁：`& $PY "$WS\code\cli.py" doctor`（0 阻塞才动手）。Anki 必须开着。

### 2.1 先看名单（演练，不写库）——默认动作

```powershell
# 只看这一集（默认）
& $PY $PICK "subtitles\Yani Neko\ヤニねこ.S01E01.…srt"

# 整季一次扫完：给目录
& $PY $PICK "subtitles\Yani Neko"

# 或者对单集显式要求扩到整季
& $PY $PICK "subtitles\Yani Neko\ヤニねこ.S01E01.…srt" --season
```

看五样：窗口几集（默认 1）、候选多少、**排序是不是「LLM 精排」**、入选的词和模型给的理由、旧标签会摘几个。
名单里混进人名/语气词/太基础的词，先别 commit，报给用户决定。

### 2.2 真写

```powershell
& $PY $PICK "subtitles\Yani Neko" --n 30 --commit
```

### 2.3 纯文本输入（不扩展目录，集数按 1 算）

```powershell
& $PY $PICK "notes\青空文庫.txt" --commit
Get-Content draft.txt -Encoding UTF8 | & $PY $PICK - --commit
```

支持 `.srt` / `.vtt` / `.ass` / `.ssa` / `.txt`；`-` 从 stdin 读纯文本。
字幕**只扫同目录、不进子目录**（`anki/` 里的重复字幕不会被数两遍）。

### 2.3b 不用模型 / 强制重排

```powershell
# 模型不可用、或本次想省时间：退回公式排序（报告会写「公式兜底」）
& $PY $PICK "subtitles\Yani Neko" --no-llm-rank

# 候选或台词没变但想重新问一遍模型（否则吃 rank_cache）
& $PY $PICK "subtitles\Yani Neko" --no-rank-cache
```

### 2.4 只清空这个标签（不选新词）

```powershell
& $PY $PICK --clear --commit
```

### 2.5 撤销上一次运行

```powershell
& $PY $PICK --revert --commit
```

`--revert` 依据 `data/daily_new/state.json` 里运行前的 noteId 集合恢复；只动
`今天学习生词` 一个标签。state 只保留最近一次运行。

### 2.6 走统一入口（等价）

```powershell
& $PY "$WS\code\cli.py" today-new "subtitles\Yani Neko" --n 30 --commit
```

## 三、选词口径（2026-11-01 起：模型排序，公式兜底）

**四段分工**，机械判断归代码、语义判断归模型：

| 段 | 谁做 | 做什么 |
|---|---|---|
| 1 抽候选 | Sudachi + 词库索引 | 逐句分词 → 词典形 → 只在三个词汇牌组命中才算候选；复合词再拼查一次。**窗口 = 输入指定的集**（默认只这一集） |
| 2 排除懂的 | 代码 | 按**笔记**判已学/挂起；JAR 门槛 1–30000；读音闸 |
| 3 排序 | **本地模型，一集一次** | 读整集台词 + 本集候选，按下面三条判据给有序名单 |
| 4 兜底 | 公式 | 模型不可用 / `--no-llm-rank` / 候选为空时才定序 |

### 3.1 模型排序（主）

判据优先级（用户定，**不要改顺序**）：

1. **动漫对白实用度**：在这类番的对白里听到能懂、说出来自然、能迁移到别的番；
   专有名词、语气词、纯功能词（こと/する/ある/いる 这类）排后。
2. **学习/编卡价值**：义项清楚、值得写中文讲解、有例句可配；太抽象、太偏门排后。
3. **一般通用度**：前两条打平时才看。

- 一集一次调用（整集台词 + 本集候选，几千 token），**不切批**；各集互不依赖 → **并行**
  （`workers = 配置里的 concurrency`，端点开几个槽用几个）。
- **模型钉在 128K 的 `qwen3.8-flash-next-iq3_s`**（`rank_gate.DEFAULT_MODEL`）。理由：本地端点
  一次只安稳服务一个模型，跟着端点当前模型走会让结果每天不同、缓存全失效；要 256K 档就得
  换载模型，会打断别的任务。临时换：`--model` / `$env:DSH_TODAY_RANK_MODEL`。
- 实测同一批 4 集：128K 与 32K 的前 30 名重合 **16/30**；32K 更容易挑进 `出来る`/`1人暮らし`
  这类过于基础的词，128K 的名单更贴校园题材。**默认 128K，32K 仅作省内存时的退路。**
- 跨集合并：每集的名次归一化成 `1 - (pos-1)/(n-1)`，多集取平均 → 多集都排得高的词分高。
- 结果缓存 `data/daily_new/rank_cache.json`；同一集同一候选集重跑不再问模型。
- 模型只给「顺序 + 一句中文理由」，**不给分数**；理由进报告，便于复查它为什么这么排。
- 每集让模型给回 `N+40` 个，代码再按名额取（`N` 内容词 + `--particles` 语气词）。
- 兜底时报告与 stdout 都会写「排序：公式兜底」——**别把兜底当成模型结果讲给用户**。

### 3.2 公式（兜底 / 参考）

```
S = ln(1+次数) + MU*ln(1+集数) + LAM*ln(30000/JAR)
```

| 参数 | 默认 | 作用 | 怎么调 |
|---|---|---|---|
| 次数项 | 权重固定 1 | 本作里出现越多分越高 | 不改 |
| `MU` | 0.3 | 跨集覆盖的加成 | `--mu 0` 完全不看跨集 |
| `LAM` | 0.3 | JAR 加成 | `--lam 0.5` 更看重高频词 |

平时它只用于：模型不可用时定序、同分参考、报告里的一列「参考分」。
次数/集数/JAR 仍然是给模型的输入（它看得见本集次数与 JAR），只是不再直接决定名次。

### 3.3 名额与去重

- **名额按词算**：N 个内容词 + `--particles` 个助词/感动词（默认 2，`0` = 不选）。
- 一个词名下**所有未学笔记**都打 tag，所以标签数可能多于 N。
- 不去重：复合词各自独立（`魔神` / `魔神族`），同词多写法也不合并。
- 候选不足 N 时有几个取几个，**不硬凑**。

## 三之二、两道词义闸（2026-10-29 加）

选出来的词还必须在**意思上**和字幕对得上，否则今天学的就是错的义项。两道闸一前一后：

**闸 1 · 读音（机械，免费）** —— 同一个词形下可能挂着读音不同的卡：

> `頭` 名下有两张卡：`あたま`（头）和 `かしら`（首领，家长）。
> 字幕说 `あたま` 时只能标前者，不能把「首领」那张一起标上。

判据：卡片 `Transliteration` / `VocabFurigana` 拆成读音集合（`から,そら` 这种多读音
要拆开、`(オ) bier,びーる` 要去括号英文），和字幕里该词的**词典形读音**取交集；
交集为空 → 这张笔记不打 tag。卡片没写读音 / 只有英文 → 放行（判不了不误杀）。

**闸 2 · 义项（语义，调本地模型）** —— 词形和读音都对，意思仍可能不同：

| 词 | 卡片释义 | 字幕句 | 实际义项 |
|---|---|---|---|
| 空 | 空的 | 同じ**空**の下に | 天空 |
| 吐く | 呕吐 | すぐ**吐く**んじゃなく吸って | 呼气 |
| 参る | 去；来；参拜 | いやいや **まいった**ね | 糟了、认输 |
| 実 | 果实 | **実は**これ | 其实 |

判据：`sense_gate.py` 把「字幕句 + 目标词 + JMdict 义项表 + 卡片中文释义」交给本地模型，
判出义项编号并回答卡片释义是否对得上。**只有模型明确判 False 才剔**；词典查不到、
模型判不了一律放行。被剔的词用后面的候选补位，并写进报告「义项核验被剔除」一节。

- 默认开；`--no-sense-check` 跳过（离线/快速跑）。
- 结论缓存 `data/daily_new/sense_cache.json`，同一句同一个词不重复判。
- 判不出来的词不丢，只有 `card_ok=false` 才拦。

## 四、输出怎么读

| 输出行 | 含义 | 正常值 |
|---|---|---|
| `窗口：1 集（只筛这一集；…）` 或 `窗口：N 集（整季/整目录）` | 这次实际扫了几集 | 默认 1；给目录或 `--season` 才多集 |
| `候选：C 个词（JAR 1–30000、有未学笔记）` | 命中多少可学的词 | 越多越好，0 说明全学完或输入没命中 |
| `排除：JAR 超范围 x / 没有未学笔记 y / 读音对不上 z` | 被硬门槛挡掉的词 | 三个数都正常存在 |
| `排序：LLM 精排（N 集 / N 次调用 / xx.xs）` | 模型参与的那几集与耗时 | 调用次数 = 有候选的集数；带「命中缓存」说明没重新问 |
| `排序：公式兜底（…）` | 模型没给出可用名单 | 偶发可接受；常发要看模型端点 |
| `分布：出现≥5 a / 跨集≥3 b / JAR≤4000 c` | 候选的粗粒度画像 | 三项越大越容易凑满 |
| `入选：30 个词 / 41 张笔记` | 内容词 + 语气词名额、标签按笔记 | 笔记数 ≥ 词数 |
| 每行的 `模型第 k｜理由` | 模型给的名次与理由 | 名次可能 > 入选数（语气词被名额压后） |
| `排序：模型定序；公式分仅作参考（1.09–4.30）` | 公式分不再决定顺序 | 分数范围可以很宽，属正常 |
| `旧标签：X 个；保留 K；摘除 R；新增 A` | 全量替换的差集 | 最终 = K + A |
| `待建卡清单：29 个词 …（演练不落盘）` | JAR 超范围/无排名的词 | 真写时会给「新增/更新/共 N」 |
| `现场复核剔除` | 两次读取之间被学过的卡 | 一般 0 |
| `回读校验通过` | 写后重查标签集合 = 入选集合 | 必须是「通过」 |
| `没有可选的词：本次不改库…` | 候选 0，旧标签保留 | 检查输入或是否已学完 |

产物（commit 后写）：

- `output/daily/today_new_words.md` —— 给人看的稳定路径报告（每次 commit 覆盖；表里有「模型理由」列）
- `data/daily_new/<日期>/picked.json` —— 机器可读：词 / `rank`（模型名次）/ `why`（理由）/
  参考分 / 次数 / 集数 / noteId（`picked[]` 顺序 = 模型的顺序 = 每日讲义的排序）
- `data/daily_new/state.json` —— 回退记录（运行前 / 运行后 noteId）
- `data/daily_new/unranked.json` —— 待建卡清单（`cli.py unranked --all` 看全表）
- `data/daily_new/rank_cache.json` —— 精排缓存（只留最近 120 组）

## 五、机械规则（脚本已做，别在提示词里重算）

- **排序键**：模型给的名次（跨集合并后）→ 公式分 → 词形。兜底模式下退化为「分数降序 → 词形」。
- **名额**：内容词 N + 语气词 `--particles`；`pick_from_order` 顺着名单取，不重排。
- **JAR 项被夹在 1–30000**：`JAR=0`、`JAR>30000`、无排名都不会算出负分或爆分。
- **词的排名**取该词所有笔记里的最小值；无排名（999999）在 JAR 门槛处被排除并登记。
- **「学过」按笔记**：该笔记所有卡 `type != 0` 才算学过；`queue == -1` 算挂起；
  埋藏（`queue == -3`）仍可选（打 tag 不解除埋藏）。
- **写前差集**：只摘 `旧 - 新`、只加 `新 - 旧`，交集不动（幂等，避免反复改 `mod`）。
- **写后回读**：`find_notes('tag:"今天学习生词"')` 必须等于入选集合。
- **回退记录**：commit 前先写 `state.json` 的 `before`，再动库。
- **清单出清**：commit 时把「这次已有范围内 JAR」的词从 `unranked.json` 摘掉。
- 打完标签后 Anki 浏览器要**切走再切回或 F5** 才刷新。

## 五之二、待建卡清单（`data/daily_new/unranked.json`）

- 收的是**词库里有卡、但 JAR 缺失 / 0 / >30000** 的词（不是「库里没有的词」）。
- 每条记：读音、JAR、本作次数/集数、首次出现的台词、`first_seen` / `last_seen`、来源字幕。
- 用来看「哪些词值得我建素材生词卡 / 补 JAR」；`doctor` 非空就报提示（退出码 2，不阻塞）。
- 用户补了 JAR（`jp-anki-jiten-rank`）后，下一次 `--commit` 运行会自动把这些词出清。
- 命令：`python code\cli.py unranked`（前 5 个）/ `--all`（全表）/ `--clear`（清空，先问用户）。

## 六、失败处理

| 现象 | 动作 |
|---|---|
| `AnkiConnect 不可用 … 请先启动 Anki` | 让用户打开 Anki，重跑（脚本幂等） |
| `牌组不存在或没有子牌组：0-日本语学习::0-词汇::…` | `jp_decks.py` 与库里牌组名对不上。**问用户**改哪边，不要自己猜 |
| `没有找到字幕文件：…` | 路径写错 / 目录里没有字幕；确认文件与编码后重跑 |
| `没有从字幕里解析出任何台词：…` | 字幕格式不认识；确认文件后重跑 |
| `没有可选的词：本次不改库` | 这段材料里没有「已有且未学」的词。别 commit，先问用户是否换输入或确实要 `--clear` |
| `排序：公式兜底（模型未给出可用名单）` | 端点没起 / 模型输出不合格。先把 stderr 的 `problems` 报给用户；要照常出名单就先这么跑，别偷偷调 `--lam` 假装是模型结果 |
| 入选不足 30 / 候选很少 | 正常（材料太短或都学过了）。**不要**去调 `--mu` / `--lam` 凑满 30，先报给用户 |
| 模型排得看不懂（全挑冷僻词 / 全挑基础词） | 先看模型理由列；确实是提示词问题就改 `rank_gate.py` 的判据并**同步升 `RUBRIC` 版本号**，不要手工改名单 |
| `回读校验失败：缺失/多出 …` | 退出码 1。先 `--revert --commit` 恢复，再把缺失/多出的 noteId 报给用户 |
| `找不到回退记录 …state.json` | 还没用本工具 commit 过；不要手工摘 tag，先确认来源 |
| 名单里出现人名/语气词/基础词 | 先给用户看；人名过滤在 `subtitle_new_words`，语气词名额由 `--particles` 控制，**不要自己改规则**或直接 `--commit` |

**不要**为了绕过上述问题去 `sqlite3` 直连库、改 `jp_decks.py`、或手工在 Anki 里批量加 tag——
工作区只走 `code/common/anki_api.py`。

## 七、收工汇报（给用户）

1. 输入是什么（目录 / 单集 / 粘贴文字）、`--n` 是多少、有没有 `--no-llm-rank`、有没有 `--commit`；
2. 窗口几集、候选多少、**排序是谁定的**（LLM 精排 N 次调用 x 秒 / 公式兜底）、入选几词几笔记；
3. 今天的词表（按模型名次，带读音、JAR、次数/集数、模型理由）；
4. 标签变化：旧标签几个、保留几个、摘除几个、新增几个，回读校验是否通过；
5. 待建卡清单这次登记了几个（`--commit` 时）；总数多少，用户可 `cli.py unranked --all` 看；
6. 回退命令：`python code\tools\today_new_words.py --revert --commit`；清空 `--clear --commit`。

## 八、与其它技能的边界

- 要把这 N 个词排到新卡队首（改 `due`）→ `jp-anki-activate`；本技能**不排期**。
- 字幕/文字的复习标签 `复习::*` → `jp-anki-subtitle-tag`；两者标签不同、可并存。
- 文字里出现、但 Anki 里没有的词 → 不在本技能范围（本技能只挑「已有且未学」）；
  JAR >30000 / 无排名的词**只登记不建卡**，建卡是 `jp-anki-mine` / 用户自己的事。
- 每日讲义 → `jp-anki-daily-lesson`；弱项分析 → `jp-anki-daily-weak`；`JitenAnimeRank` 回填 → `jp-anki-jiten-rank`。
- 本技能**只加/摘一个标签**，别的阶段要动卡请加载对应技能。
