# JMdict 查证（jmdict-lookup）

一句话定位：**这是你的词典，不是你的老师。** 它只给事实（词形、读音、词性、义项、
限制、语域、英文释义），判断仍然由你做；它也不会替你写讲解。

> **什么时候先查**：只要你对一个词的**语义边界**有一丝不确定，就先查一遍再说话。
> 查一次的成本是几行输出；猜错的成本是一张写错讲解的卡，而且没有 `git diff` 能退。

---

## 一、疑惑清单 → 查什么

| 你的疑惑 | 先跑 | 看哪一项 |
|---|---|---|
| 这个词有几个意思？这里取哪个？ | `lookup 词` | 义项编号 `1) 2) 3)` + 每个义项的英文释义 |
| 这个读音对应哪些义项？（上手/上手い） | `lookup 词` | `适用:` 行的 `读音=` / `笔形=` |
| 词性是什么？自动词还是他动词？ | `lookup 词` | 每个义项 `｜` **前面**那串：`一段·他动`、`五段·ウ·自动` |
| 这是近义词还是同义词？差在哪？ | `lookup 词A 词B` | 两边的义项与 `参考:` / `反义:` |
| 是古语 / 方言 / 俚语 / 书面语？ | `lookup 词` | `〔古语〕〔关西〕〔俚语〕〔通常写假名〕` |
| 是惯用句还是普通词组？ | `lookup 词` | 词性里的 `惯用句`（`exp`） |
| 这是专有名词吗？怎么读？ | `lookup 词` → `name 词` | 先看 JMdict，未命中再看 JMnedict |
| 单个汉字的意思 / 音训读？ | `char 字` | 音读、训读、义、学年、笔画 |
| 英文里怎么说这个词？（反向找词） | `meaning "to eat" --short` | 候选条目一行一条 |
| 一批词的读音要核对 | `lookup a b c --json` | 一次进程查多个，省启动开销 |

**不要**为了"确认自己没记错"去查一个你 100% 确定的常用词——那是浪费一轮工具调用。
**要**在下面这些地方查：字幕里没见过的写法、听起来像方言的腔调、拟声词、
汉字相同但读音不同的词、`Sentence` 里读不通的那个词、专有名词（人名/地名/招式名）。

## 二、快速开始

```powershell
$PY = "python"
$JD = "$PWD\.dsh\skills\jmdict-lookup\scripts\jmdict.py"    # 工作区根目录下执行

& $PY $JD status                 # 库在不在、多大、什么版本
& $PY $JD lookup 食べる           # 主查询（汉字或假名）
& $PY $JD lookup 上手 --senses 4  # 一词多义：多看几个义项
& $PY $JD lookup やばい エグい --json
& $PY $JD meaning "to eat" --limit 5 --short
& $PY $JD char 食
```

输出是**给模型读的紧凑文本**，不是给人看的排版。一次 `lookup` 通常 10–25 行；
`--senses` / `--glosses` / `--limit` 控制长度，别一上来就 `--senses 20`。

## 三、输出怎么读

```
── 上手 ──
1. 上手【じょうず】 ★常用 id=1353320
   读音: じょうず★、じょうて、じょうしゅ
   1) ナ形容词·名词｜skillful; skilled; proficient; good (at)
      反义: 下手【へた】[义项1]
   2) 名词｜flattery
2. 上手【うわて】 id=1580400
   读音: うわて、かみて
   1) ナ形容词·名词｜upper part
   2) 名词｜upper stream; upper course of a river
      适用: 读音=かみて
```

| 记号 | 含义 |
|---|---|
| `★常用` / 词形后的 `★` | JMdict 标为高频（ichi1/news1/spec 之类），不是考试级别 |
| `笔形:` / `读音:` | 只在**有多个**写法时打印；单写法不占行 |
| `〔…〕` | 语域/领域标签，已译成中文（古语、俚语、关西、计算机、通常写假名…） |
| `适用: 读音=X` | **这一条义项只适用于该读音/笔形**——一词多义辨析的关键 |
| `说明:` | JMdict 的英文注解（用法限制、搭配、文化背景） |
| `参考:` / `反义:` | 交叉引用到别的词条（`词【假名】[义项号]`） |
| `id=…` | JMdict 条目 ID，可 `id 1353320` 复现同一条 |
| `未命中` + `试过:` | 精确匹配失败，并列出实际试过的写法 |

**认不出的标签**会以 `代码(英文说明)` 出现——那是 JMdict 自带标签表，
说明本技能的映射没覆盖到，不是错误。

## 四、语义澄清的四步法（照做，别跳）

1. **定形**：先确认查询串是**词典形**。`食べた` / `食べて` / `食べられる` 查不到，
   要查 `食べる`；形容词查 `ない` 形词干（`高かった` → `高い`）。脚本**不做活用还原**。
2. **定读**：看 `读音:` 行有几个，再用每个义项的 `适用:` 判断**这个读音管哪几条义项**。
   这一步能解决大部分「读音相同、汉字相同、意思不同」的坑。
3. **定界**：把义项按 `〔…〕` 和英文释义分成几组，用**上下文**（例句、前后文、人物关系）
   排除不合语境的义项，只留一条；留两条就说明**这里真的歧义**，要回去看原文再说。
4. **落结论**：报告时写清「取第 N 条义项，理由是 X」；不要只把一堆英文释义抄回来。

> **只引用查到的内容。** 查到的义项里没有的意思，不要补；补了就等于又猜了一次。

## 五、命令与参数

| 子命令 | 作用 | 常用参数 |
|---|---|---|
| `status` | 库状态：路径、大小、版本、条目数 | — |
| `build` | 首次建库 / 重建（**联网**，~11–25 MB） | `--common`（只常词，覆盖差）、`--no-names`（省 ~300 MB）、`--force` |
| `update` | 查新版 | `--check`（只查不装） |
| `lookup 词…` | 主查询：汉字/假名**精确**匹配（+ 名字/单字兜底） | `--limit 8` `--senses 6` `--glosses 4` `--json` |
| `reading 假名…` | 只走读音索引 | `--senses` `--glosses` |
| `meaning 英文…` | 英文释义全文搜索（FTS5） | `--limit 10` `--short` `--fts` |
| `name 名字…` | JMnedict 人名/地名/作品名 | `--limit 10` |
| `char 字…` | Kanjidic 单字 | — |
| `id 1353320…` | 按条目 ID 取 | `--senses` `--glosses` |

全局：`--data-dir DIR` 换库位置（默认 `<工作区>/data/dict/jmdictpy`）。

**批量查**：`lookup 词A 词B 词C` 一个进程查完，比三次调用省启动时间；
`--json` 输出单行紧凑 JSON（`{"query","tried","hit","entries":[…],"names":[…],"characters":[…]}`），
字段形状稳定，适合程序化再加工。

## 六、退出码：机械分支，别靠读输出判断

| 码 | 含义 | 你该做什么 |
|---|---|---|
| `0` | 有命中 | 读义项，进入四步法第 3 步 |
| `1` | 未命中（查询合法，词没查到） | 按 `试过:` 换形/换假名/换 `name`/`char`；仍无 → 承认查不到，别编 |
| `2` | 参数错误 | 改命令 |
| `3` | 环境问题（jmdictpy 没装 / 库没建 / 下载失败） | 见 §八 |

## 七、已知限制（都是真的，别指望）

* **只做精确匹配**。没有前缀、模糊、`～` 通配；自动兜底只有两项：
  全角→半角（NFKC）归一、**平假名⇄片假名互转**（`タベル`↔`たべる`，同一串音）。
* **不做活用还原**：`食べた`、`行って`、`高かった` 查不到，要自己还原成词典形。
* **释义是英文**（JMdict 没有中文）。`meaning` 子命令也只搜英文——中文关键词请先译成
  一个英文短词再搜（`吃` → `eat`，`吵架` → `quarrel`）。
* **只覆盖标准日语词典**：网络新词、作品造语、角色名、部分专有名词可能完全没有。
  这类词 `lookup` 未命中是正常结果，用 `name` 再试，然后交给上下文判断。
* **词形以 JMdict 为准**：它收 `食べる`，不收 `食べる？`；送假名不同写法（`引く`/`ひく`）
  分别查。
* **不联网**（`build` / `update` 除外）。`auto_update` 在本技能里永久关闭——查词不该等网络。
* **只读**：不写 Anki、不写任何文件（`build` 只建库）。

## 八、装在哪 / 建库 / 更新

| 东西 | 位置 |
|---|---|
| 技能本体 | `<工作区>/.dsh/skills/jmdict-lookup/` |
| 查询脚本 | `scripts/jmdict.py` |
| Python 库 | `<工作区>/data/pylibs/jmdictpy`（工作区本地，删目录即卸载） |
| 词典库 | `<工作区>/data/dict/jmdictpy/jmdict.db`（全量 218,930 条，551 MB）+ `version.json` |

首次建库（已在 2026-10-24 建过；换机/删库后才需要）：

```powershell
& $PY code\oneshot\install_workspace_wheels.py jmdictpy   # 装库（幂等，会更新 pylibs.lock.json）
& $PY $JD build                                          # 下字典 + 建 SQLite（1–3 分钟）
& $PY $JD status                                         # 复核
```

> **`build` 不直接调 `JMDict()`**：jmdictpy 0.1.1 的 `get_download_urls` 用
> `startswith("jmdict-eng")` 匹配资产，会把 `jmdict-eng-common-…` 也命中，
> **永远装成 22,647 条的常词库**。本脚本在 `_release_urls()` 里改成
> `jmdict-eng-<数字>` 精确匹配，才拿到全量。升级 jmdictpy 后如果上游修了，这里可以简化。
> 库太大想瘦身：`build --no-names`（省 ~300 MB，`name` 子命令失效）或 `--common`（22k 条，覆盖差）。

版本更新：`& $PY $JD update --check` 看有没有新版，`& $PY $JD update` 装。
字典数据来自 [jmdict-simplified](https://github.com/scriptin/jmdict-simplified) 的
GitHub Release，受 EDRDG 许可约束；**不用**它做商业分发。

## 九、故障排查

| 现象 | 处理 |
|---|---|
| `jmdictpy 没装` / exit 3 | `& $PY code\oneshot\install_workspace_wheels.py jmdictpy` |
| `词典库还没建` / exit 3 | `& $PY $JD build` |
| `build` 卡在下载 | 需要 GitHub 可达；公司网/代理挂了就换网，别反复重试 |
| `未命中` 但词明明存在 | ① 还原成词典形 ② 换汉字/假名写法 ③ 汉字词用 `lookup`、假名用 `reading` ④ 专有名用 `name` |
| `meaning` 搜不到 | 只索引英文释义；换英文短词，或 `--fts "eat*"` |
| 输出里的标签是 `xx(英文)` | 映射没覆盖，不影响判断 |
| 慢（>1s/次） | 单次约 0.5–0.8s（Python 启动 + 开库占大头）。**一次查多个词**（`lookup a b c`）只付一次启动成本 |
| 库太大想瘦身 | `build --common --force` 重建常词库（覆盖变差，不推荐） |

## 十、汇报口径

查完向用户/下游报告时给这四项，不要只贴词典原文：

1. **查了什么**：`lookup`/`reading`/`meaning` + 查询串（词形、是不是还原过）；
2. **命中什么**：条目 ID、笔形/读音、命中第几条义项（写编号）；
3. **怎么定的**：用哪个 `适用:`/语域/交叉引用排除了别的义项——一句话说清；
4. **还存疑的部分**：查不到、或两条义项都说得通时**明说**，不要假装确定。
