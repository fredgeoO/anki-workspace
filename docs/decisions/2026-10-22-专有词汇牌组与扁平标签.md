# 专有词汇牌组：`3-专有词汇` + 专用笔记类型 + 扁平标签

> 状态：active ｜ 日期：2026-10-22 ｜ 相关：`code/execution/proper.py`、
> `code/tools/proper_extract.py`、`code/common/check_proper.py`、
> [使用说明](../proper-noun-使用说明.md)

## 背景

专有名词在旧逻辑里只有「排除」一条路：

- `mine.py` 的 `MINE_INSTRUCTION` 明确写「专有名词 → `include=false`」（那边挖的是要背的词）；
- `vocab_cover` 的 `jp_tok.py` 把 `固有名詞` 归到 `proper` 档位（「跟着剧情自然学会，不算词汇量」）；
- `newwords.py` / `crosswork.py` / `work_concepts.json` 把「作品专有概念 + 纯人名」判成不挖；
- `subtitle_new_words.py` 默认 `--include-names=false`。

这些判断**本身是对的**，但它们让专名被判定后**直接丢弃**，没有回收通路。
用户要的是「认得就行」的收集品：角色名、地名、组织、概念、技能、种族、称号，
以及跨作品同名（不同作品都叫 David → 两张卡）。

## 决策

### 1. 新建牌组 + 新建专用笔记类型

- 牌组：`0-日本语学习::0-词汇::3-专有词汇`（常量 `jp_decks.DECK_PROPER`）。
- 笔记类型：`Japanese Proper Noun`，字段
  `Index / Word / Reading / Meaning / Categories / Intro / Intro Translation / AINote / Source / Word Audio`。
- **为什么新建而不是复用**：现有的两个模板都是「听音/句子先行」——
  `Japanese Vocabulary` 正面只有 `Word Audio` + 词性（看不到词形），`Basic`（例句卡）正面只有原声 + 图。
  而这里的回忆方向是**看词形 → 想读音与意思**，正面必须只有 `Word`。
- **首字段放 `Index`**：Anki 的查重只看笔记类型首字段。用 `Word` 当首字段会让
  「同名不同作品」在 `addNotes` 阶段被拒；放唯一序号后两张卡天然共存，
  真正的查重由脚本的 `(归一化词形, 出处)` 负责。
- 模板与 CSS **以代码为准**（`proper.py` 里的常量），`model --check` 检测漂移，
  默认只报告；覆盖必须显式 `--force-templates`，避免有人手改卡面后悄悄分叉。

### 2. 类别标签扁平；出处标签继承 `动画::<作品>`

```
专有名词                                 必有
人名 / 地名 / 组织 / 概念 / 技能 / 种族 / 称号 / 作品名 / 其他   1..n（扁平）
动画::水星领航员                          出处：两层，**不带季度/集数**
```

理由（2026-10-22 用户口径）：
- **类别**一个专名可以同时属于多个（`メリオダス` = 人名 + 称号）。层级标签会把类别压成
  单值树，表达不了；所以类别一律平级。
- **出处**复用库里已有的动画标签命名空间，但**只取两层**：例句卡是
  `动画::水星领航员::第一季::第04集`，专名卡挂 `动画::水星领航员` ——
  `tag:动画::水星领航员` 一次搜到两种卡（实测 231 = 188 例句 + 43 专名），
  而季度/集数对"这个名字属于哪部作品"没有信息量，反而会把标签树撑成每集一条。
- 非动画出处（`亚瑟王传说`）就是一条裸标签。
- **不写批次/日期标签**（同日用户口径：没必要）。回滚按「牌组 + 出处标签」圈范围，
  要按批就靠浏览器 `Added` 列排序。`work_tag_from_tags()` 会跳过历史遗留的
  `专有名词-批次-*`，去重键不受影响。

**保留字**：`专有名词`、九个类别名 —— 别在别处用同名标签表达别的意思。

「关联/原型」（`related`）**不进标签**：实测模型把它当「相关词」用（`晃`→`蓝华`、
`オレンジぷらねっと`→`アリア社`），当标签就是噪声；它写进 `AINote` 的「关联：」段。

### 3. 收集品，但不进学习队列

- 脚本**不写** `due`/`type`/`queue`，**不调用** `suspend`，**不改** `saveDeckConfig`；
- `write` 收工只打印该牌组当前 `new/day`，并给出两种手动停学方式
  （牌组选项 new/day=0；浏览器全选挂起）。

理由：用户明确要自己控制什么时候停/学；脚本一旦替用户做调度决策，
就变成「悄悄把 900 个名字塞进今天的队列」——正是旧逻辑当初要避免的事。

### 4. 提取走原子能力，字幕只是调用方

`code/tools/proper_extract.py`：**一段文字 + 背景 → 专名清单**，Anki 无关、可单跑。
`proper.py` 只负责字幕切窗、三路提示（Sudachi 固名 / 生词残差 / 片假名长串）、
合并、判据、写库。提取口径只有一份实现 —— 出问题能拿一句话复现，
不用重跑一整集；文章、小说段落也能复用。

**不回溯旧例句卡**：提取源是字幕文件（按集手动跑）。旧例句卡保留它们的用途
（挖生词、覆盖率），不在这里二次加工。

### 5. 收录判据

- 只收 `core6000` + `考级词汇` + **`素材生词`** 里**都没有**的专名（`--include-known` 可关掉）。
  前两个档掉 `日本`/`東京`/`王子`/`悪魔` 这类被 Sudachi 误判成固名的普通词；
  第三个档掉「已经挖成生词卡」的词（实测 `ゴンドラ`：已在素材生词里，不该再收一张专名卡）。
  代价是 `シングル`/`プリマ` 这种「既是普通词又是本作称号」的会漏，
  所以 `report.md` 单列「可强收」清单。
- 纯假名名字只认**精确**匹配，不走 kata2hira 变体表：否则 `アンナ`（人名）会被
  `あんな`（那样）误判成"已存在"（2026-10-22 实测）。含汉字的词仍走活用/变体反推。
- 名字后面的敬称要剥掉（`晃さん`→`晃`、`アイちゃん`→`アイ`）；`アリア社長` 这类职务是名字的一部分，不动。
- 同名不同出处 = 不同的卡；同作品多处出现 = 一张卡（取首例句）。

## 后果

| 影响面 | 结论 |
|---|---|
| `today_new.py`（每日讲义） | 不受影响：`STUDY_UNITS` 里没有新牌组，字段名也不同 |
| `collect_vocab.py`（覆盖率） | 不受影响：`DECK_SPECS` 未登记 → `logical_of()` 返回 `''` 整牌跳过 |
| `jiten_reorder` 插件 | 不受影响：`config.json` 的 `decks` 只有 `0-素材生词` |
| `activate.py`（阶段 3） | 不受影响：只索引考级词汇 / core6000 / 两个标签类 |
| `mine.py`（阶段 4） | **判据不动**：生词牌组仍不收专名；两边互不覆盖 |

## 实施时踩到的坑（已修，写在这里防复发）

**去重键两处口径不一致 → 重复建卡**。`existing_keys()` 用「出处标签」做键，
而 `write_cards()` 还用「裸作品名」做键；换标签后键永远对不上，重跑一次多出 43 张
（Index 44–86 全是重复卡，无音频，已删）。修法：收敛到 `proper.card_key(word, work_tag)`，
建卡 / 校验 / 写库 / 查重全部只走这一个函数；回归测试见
`code/tests/test_proper_patch.py` 的「去重键」两条断言。

> 另注（2026-10-22）：中途曾把「批次标签消失」误判成 AnkiConnect `replaceTags` 的副作用，
> 实际是用户手动删掉了那个标签（也是本 ADR 里取消批次标签的由来）。`anki_api.replace_tags`
> 保持原生单次调用，未做改动。

## 什么时候该重新考虑

1. 想让专名卡进每日讲义 → 要在 `today_new.STUDY_UNITS` 里加一个单元并适配新字段（另开 ADR）。
2. 想全量回溯历史例句卡 → 那是另一条采集策略，`proper.py scan` 只吃字幕/文本。
3. 需要一个「按批回滚」的抓手（目前没有批次标签）→ 再评估加「导入日期」标签还是靠 `Added` 列。
4. 出现「同一作品里同名不同角色」需要拆卡 → 去重键要加角色维度。
