# 三内核 + 写库收口：代码简化重构（2026-11）

> 状态：active ｜ 最后核实：2026-11-01

## 背景

2026-11-01 盘点出的四个具体问题：

1. **写库纪律没有落到代码**：30 个文件出现 `--commit`，只有 7 个调用
   `AK.verify_note_fields`；“写后回读”靠自觉。
2. **批处理生命周期各写一遍**：`mine.py` 与 `pipeline.py` 各有一套
   split / manifest / 跳过已存在批次 / failed.json。
3. **编排靠字符串路径**：`episode.py` 用 subprocess 调兄弟脚本，retag 调用的
   `oneshot/retag_notes.py` 已被移入 `archive/`，标准用法必在最后一阶段失败。
4. **巨石与重复渲染**：`today_new.py` 3160 行、`core6000_example.py` 2943 行；
   `<ruby>` 标签至少 4 处手拼。

## 决策

1. **写库只走 `common/writeback.py`**：`write_fields` / `write_tags`，
   演练→备份→写→回读一次到位。**不暴露任何调度接口**（不 import
   `set_card_due` / `set_card_values` / `forget_cards`），所以铁律 5 是结构保证。
2. **批处理清单只走 `common/batchjob.py`**：`split` / `todo` / `run` / `failed.json`。
   内层生成循环（mine 按 word 重问、pipeline 按 noteId 重问）保留在各自脚本——语义不同，
   不硬并。
3. **cli 一张扁平表**：`ENTRIES`（tuple key）+ `resolve()`，`vocab` / `weak` / preset
   不再各写一路 if；旧命令全部保留为别名。
4. **`<ruby>` 标签只有一个构造器**：`ruby_engine.wrap`；`today_new` 与 `core6000`
   的调用点都切过去。
5. **纯函数出巨石**：`common/ruby_text.py`（注音解析）、`common/htmltext.py`（去标签）、
   `execution/lesson_text.py`（teach 整形/接续/渲染）、`execution/core6000_text.py`
   （② 的词性/注音/词表）、`execution/lesson_check.py`（讲义的机械判定：词形/读音/词性、
   内容问题、渲染后闸门）。
6. **阶段边界按能力选择**：有干净函数入口的（retag、rank）改 import；
   只有 argparse CLI 的（pipeline/mine/mine_audio/ruby_engine）保留 subprocess，
   但路径统一进 `episode.SCRIPTS` 并在启动时 `check_scripts()`。

## 采纳范围与例外

- 已迁：`cards` / `subtitle_tag` / `ainote_enrich` / `core6000_meaning` /
  `episode` retag / `freq_external`（`--tag`、`--models`、`--plan/--all-notes` 三条路径）。
- 保留：
  - `tag_freq_stop`：按批次累计已写 nid，中途失败可精确 `--revert`；内核目前没有
    `on_chunk` 回调，迁过去会丢能力。
  - `mine` / `proper` / `immersionkit`：**新建笔记**，writeback 只更新既有笔记。
  - `activate`：写 `due`（调度列），本来就不该进 writeback。
  - `core6000_example`：**写库仍是自有事务**（`data/core6000/backup_*.json` + `revert`）：
    apply 除了回读写入值，还验「没写的字段与写库前逐字相同」，而 `writeback` 只验前者；
    所以先只外提纯渲染（见决策 5），写库等内核补上这条校验（或把 `revert` 并进内核）再谈。
  - `immersion_api`：手拼 `<ruby>` 前先 `escape_html`，且 `HAN_RE` 含兼容汉字区；
    换成 `wrap` 会改变边界行为。
