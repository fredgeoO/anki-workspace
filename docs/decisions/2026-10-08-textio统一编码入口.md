# ADR：文本 I/O 与编码统一到 `textio.py` 单一入口

> 状态：active ｜ 最后核实：2026-10-10 ｜ 日期：2026-10-08

## 背景

本机 Windows 默认代码页 936（GBK），Python 在**管道/重定向**时按 locale 取 stdio 编码，
于是打印日文会 `UnicodeEncodeError: 'gbk' codec can't encode character`，
或者在 GBK 编得出来的汉字上**静默乱码**。历史上各脚本自己打补丁 ——
手写 `sys.stdout.reconfigure(...)` 的有 20+ 处，读 JSON 各自写解码逻辑，
子进程用 `subprocess.run(text=True)` 又踩同一个坑。

**2026-10-08 的事故**（真正的触发点）：用 PowerShell 5.1 的
`Get-Content cmp_out.json -Raw | ConvertFrom-Json` 读 UTF-8 产出，
`ConvertFrom-Json` 报「传入的对象无效」，`$o` 为 `$null`，
于是「字段为空就删」的判断对**每一个**文件都成立 ——
误删了 `output/cmp4` 里 39 个产出（回归结果丢失，只能重跑）。

## 决定

1. 所有会直接跑的脚本（115 个）一律 `import textio`；`import` 即 `setup()`，
   把 stdio 钉成 UTF-8（幂等），并在环境里种下 `PYTHONIOENCODING/PYTHONUTF8`。
2. 读文件走 `textio.read_text` / `load_json`（自动判 UTF-8/BOM/UTF-16/GBK/CP932，
   不是 UTF-8 会在 stderr 出声）；子进程走 `textio.run`（修好子进程环境 + 文本模式）；
   stdin 走 `textio.read_stdin`。
3. **不许再手写 `sys.stdout.reconfigure(...)`** —— `textio.py audit` 会把它当回退抓出来
   （R1）；R2 = 会直接跑的脚本没 `import textio`。R1/R2 为 0 是**硬门槛**，
   R3-R5（文本 open 没写 encoding / PS 缺 `-Encoding` / 直接用 `sys.stdin`）在 `--strict` 下也卡。
4. PowerShell 侧配套 `code/common/ps-utf8.ps1`（把 `Get-Content` 等默认参数钉成 utf8）；
   但 DSH 的 shell 是受限令牌，`.ps1` **跑不了**，只能用
   `iex ([IO.File]::ReadAllText(...,[Text.Encoding]::UTF8))` 读进来执行
   （细节见 [docs/architecture.md §6.1](../architecture.md)）。
5. 判断、筛选、删除的确认一律在 Python 里做；**任何删除/覆盖前先打印
   「将删 N 个」清单与计数，数字不符就 abort**（§6.2）。

## 理由

- 编码是**横切关注点**：一处没接上就出乱码，而乱码的下游是**误判**（不是报错），
  最难查。单入口才能被审计。
- 让「回退」变成可检测的：`textio.py audit` 是新写/改脚本时的防回退网，
  现在收进 `doctor` 第 3 项，开工前必跑。

## 影响

- 新脚本少写一堆样板；但**必须**记得那一行 `import textio`，否则 R2 会拦。
- 迁移前的完整备份在 `data/evidence/textio_migration_backup/`（code / skills /
  core6000-analysis 三棵树，回退就是拷回去）——**这是冻结证据，不要再编辑**。
