# 素材生词卡 · Agent 执行指令

> 状态：active ｜ 最后核实：2026-10-11

**这是什么**：阶段四子代理的执行规范 —— 把候选残差判定成 6 个字段的生词卡条目。
**为什么存在**：同阶段二；「是不是一个词、词典形是什么」只能由模型判，但形状必须固定。
**什么时候读**：本地模型端点不可用、要派子代理判定生词候选时。

> 与 [jp-card-agent-instruction.md](jp-card-agent-instruction.md)（字幕例句卡）的分工：
> 那份是**给整句写讲解**，这份是**给单词写词条**。相同的是 ruby 与标签的硬约束。

---

## 0. 背景：为什么候选长得很脏

生词不是查出来的，是**减出来的**：脚本拿「已有词汇牌组」的全部词典形
（`0-词汇::2-考级词汇` 10,609 张 ＋ `0-词汇::1-高频日语单词 6000` 6,000 张，
合计 11,728 词 / 229,007 种可识别写法）在例题句里做**句内最长匹配**，
把已知词覆盖掉，剩下的连续片段就是 `word` 字段里的候选。

覆盖用的是词典形 + 活用变体 + 功能词表（助词/助动词），**不可能穷尽**，所以候选有三种：

| 类型 | 例子 | 你的判断 |
|---|---|---|
| **A. 真的生词** | `漕ぐ`（划船）、`突如`、`継承`、`貫禄`、`叶う` | `include: true` |
| **B. 残缺碎片** | `満ち溢`（←満ち溢れる）、`食べ終`（←食べ終わる）、`魔スマイル`（←小悪魔スマイル） | 能还原成**一个确切的词**就收（补全词典形），还原不了或只是切坏的片段就 `false` |
| **C. 专有名词 / 语气词 / 无学习价值** | `河合`・`藍華`（人名）、`アクア`・`アリシア`（作品设定）；`ダクネス`（别作人名） | `include: false` |

**脚本已经把「已存在于两组牌组」的活用形全部剔掉了**（`食べ`・`信じ`・`忘れ` 这类
不会出现在你的输入里 —— 它们已由 `食べる`・`信じる`・`忘れる` 覆盖）。
所以你的输入里每一条都**不**在 core6000 / 考级词汇中，你不需要再查这一点。
但**你补全后的词典形**会被脚本再查一次：如果你把 `漕い` 补成 `漕ぐ`，而 `漕ぐ`
其实已经在牌组里，这张卡会被自动剔除并在校验报告里列出来——这是有意的安全网。

## 1. 输入契约

`data/vocab/gen_mine/input_NN.json`，JSON 数组，每项：

```json
{
  "word": "満ち溢",
  "count": 1,
  "scripts": "kanji",
  "len": 3,
  "tags": [],
  "kana_only": false,
  "occurrences": [
    {"noteId": 1234567890123,
     "sentence": "アクアはいつか必ず 幸せで満ち溢れた星になる",
     "sentence_html": "<ruby>幸<rt>しあわ</rt></ruby>せで<ruby>満<rt>み</rt></ruby>ち<ruby>溢<rt>あふ</rt></ruby>れた<ruby>星<rt>ほし</rt></ruby>になる",
     "source": "Aria The Animation 04.jp.srt"}
  ]
}
```

| 字段 | 说明 |
|---|---|
| `word` | 候选残差。**不是**干净的词，可能是碎片 |
| `count` | 该残差在全部例句里出现几次 |
| `scripts` | `kanji` = 含汉字；`kana` = 纯假名/片假名 |
| `occurrences[].sentence` | 纯文本例句；`sentence_html` 是**已入库的带振假名版本** |
| `occurrences[].source` | 出处文件名，用于判断语域（动画口语 / 新闻 / 纪录片旁白） |

`sentence_html` 已经是校验过的振假名（原例句卡的 `Sentence HTML` 字段），
脚本会**原样复用**它作为生词卡的例句，**你不需要、也不允许重新生成它**。
它只用来帮你判断词形和读音。

---

## 2. 输出契约

写入 `data/vocab/gen_mine/output_NN.json`，JSON 数组，**每一条输入对应一条输出，顺序一致**：

```json
[
  {"word": "満ち溢", "reading": "みちあふれる", "pos": "自动词",
   "meaning": "充满、洋溢", "translation": "水星终将变成一颗充满幸福的星球。",
   "a_note": "<p>…</p>", "include": true, "reason": ""},
  {"word": "河合", "reading": "かわい", "pos": "名词", "meaning": "河合（姓氏）",
   "translation": "", "a_note": "", "include": false, "reason": "日本人姓氏，专有名词，不是需要学的词"}
]
```

| 字段 | 规则 |
|---|---|
| `word` | **词典形**。`満ち溢`→`満ち溢れる`；`食べ終`→`食べ終わる`；本身就是词典形就原样回填。还原不了就原样。**必须与输入的 `word` 有对应关系**（允许 `〜` 与全半角差异），不能凭空换一个词 |
| `reading` | 上面词典形的**平假名**读音，纯假名，不带 `[]`、不带 `<ruby>`、不带空格 |
| `pos` | 只能取：`名词` `イ形容词` `ナ形容词` `自动词` `他动词` `副词` `接续词` `外来语` `惯用句`（动词自他不明时用 `他动词` 或省略整个 `pos` 会不合格，请务必选一个） |
| `meaning` | 简洁中文释义，多个义项用 `；` 分隔 |
| `translation` | `occurrences[0].sentence` 的自然中文翻译，一句 |
| `a_note` | 词条讲解，见第 4 节。`include: true` 时必填 |
| `include` | `true` = 收进生词牌；`false` = 不收 |
| `reason` | `include: false` 时**必填**，一句话说明（例：`人名`、`已是「食べる」的活用`、`切坏的碎片，还原不出词`）|

> `include: false` 的条目 `reading/pos/meaning/a_note` 可以留空，但 `reason` 不能空。

## 3. 判定标准（`include` 怎么定）

**收（true）**——同时满足：

1. 是**日语里真实存在的词**（能写出词典形、能给出读音）
2. 确实**不在** core6000 / 考级词汇里（脚本已保证输入满足，但补全词典形后要复核）
3. **有学习价值**：不是纯粹的专有名词，不是语气词，不是数字

**不收（false）**——命中任一条：

| 情况 | `reason` 示例 |
|---|---|
| 人名、地名、作品设定名 | `人名（角色名）` |
| 切坏且还原不出确切词的碎片 | `碎片，无法还原成具体词` |
| 语法句型的片段 | `〜なくちゃ` 的一部分，语法已在 1-语法 牌组 |
| 只是已知词的活用形（脚本漏网的） | `「食べる」的活用形` |
| 语气词 / 感叹词 / 拟声词没有固定语义 | `感叹词，无固定语义` |
| 公司名/品牌/商品名 | `品牌名` |

**片假名外来语的取舍**：`セリフ`（台词）、`ケンカ`（吵架）、`イルカ`（海豚）这类
已经彻底日语化、且你大概率不认识的词，**可以收**；
`オッケー`・`オーケー`（OK 的两种写法，重复）、`ビュー`（view 的直译）、
`テイク`（take，只出现在「テイクオフ」里）这类**英语母语者一眼就懂、或只是片段的**，
判 `false` 或只收其中一个代表形。同一个词的多种片假名写法（`オッケー`/`オーケー`）
**只收一个**。

**词形归一**：如果两条输入其实是同一个词的不同切片/写法，只给其中一条 `include: true`，
另一条 `false` 并注明 `与「X」重复`。

## 4. `a_note` 结构规范

固定四段，每段一个 `<p>`（**第 4 段按需出现**）：

```html
<p><b>中文翻译：</b>该例句的自然中文翻译。</p>
<p><b>核心词汇：</b><br><ruby>満<rt>み</rt></ruby>ち<ruby>溢<rt>あふ</rt></ruby>れる：自动词（一段）。充满、洋溢。</p>
<p><b>语法要点：</b><br>该词在句中的接续与功能（如「〜で満ち溢れる」的整体结构）。</p>
<p><b>动词变形解析：</b><br><ruby>満<rt>み</rt></ruby>ち<ruby>溢<rt>あふ</rt></ruby>れる（原形）→ <ruby>満<rt>み</rt></ruby>ち<ruby>溢<rt>あふ</rt></ruby>れ（連用形）→ 満ち溢れた（た形）</p>
```

- **`核心词汇` 段必须以本卡这个词为首条**（它就是本卡的学习对象），格式：
  `词形：词性。中文释义。`
- `语法要点` 写该词在**例句里**的接续和功能，不要堆词典里所有用法
- `动词变形解析`：只有例句里**真实发生了活用**才写这一段。名词、イ形容词、副词一律省略整段
- 整段 `a_note` 控制在 250 字以内 —— 这是复习卡，不是词条页

---

## 5. 硬约束（违反任何一条即为不合格）

1. **只用标签白名单**：`<p>` `<br>` `<b>` `<ruby>` `<rt>`。
   禁止 `<div>` `<span>` `<style>` `<table>` `<ul>` `<li>` `<h3>`，禁止任何 `class=` / `style=`
2. **禁止 LaTeX**：不出现 `$...$`、`\rightarrow`、`\to`。推导用全角箭头 **→**（U+2192）
3. **禁止反斜杠 `\`**
4. **禁止半角双引号 `"`**；需要引号用「」
5. **禁止 Markdown**：不要 ```` ``` ````、不要 `**加粗**`
6. **日语汉字必须标 ruby**（含 `a_note` 里的所有日语词）；**中文汉字绝对不标**
7. **送假名放在 `<rt>` 之外**：`<ruby>食<rt>た</rt></ruby>べる`，不是 `<ruby>食べる<rt>たべる</rt></ruby>`
8. **纯假名不加 ruby**（`なる`・`ある` 不要 `<ruby>と<rt>と</rt></ruby>`）
9. **敬语接头辞 `お`/`ご` 放在 `<ruby>` 之外**：`お<ruby>墓<rt>はか</rt></ruby>`
10. `word` / `reading` / `pos` / `meaning` 字段里**不放**任何 HTML 标签
11. `a_note` 的 `中文翻译` / `核心词汇` / `语法要点` 三段**必须存在**（第 4 段可选）

## 6. 执行流程

> **批处理路径（2026-10-11 起）**：这一步默认由 `mine.py gen` **直连本地模型**完成，
> 提示词正本 = `code/execution/mine.py` 的 `MINE_INSTRUCTION`（本文件是它的说明版）。
> 本地模型判不出来的条目写进 `gen_mine/failed.json`，由强模型（deepseek）出 `fix_output.json`
> 再 `mine.py merge-fix` 并回。下面的步骤是那条路径的行为描述。

1. 读 `data/vocab/gen_mine/input_NN.json`
2. 逐条判定 + 生成
3. 写入 `data/vocab/gen_mine/output_NN.json`（数量与顺序与输入一致）
4. **校验只做一次，且由脚本做**：`gen` 内部用 `check_mine.py` 机械判一次，不合格的**只重问那一轮**；
   仍不合格的按"不收"处理（`include=false` + 原因）。**生成方不要自己跑自检脚本、
   更不要"跑到 0 不合格"** —— 那是把同一份校验算两遍。
5. **汇报**：`include=true / false` 各几条、判断不了的条目

**禁止**：不要调用 AnkiConnect、不要写 Anki、不要改输入文件、不要动 `data/vocab/gen_mine/` 之外的任何文件。

## 7. 自检清单

- [ ] 输出条数 = 输入条数，`word` 与输入一一对应
- [ ] `include: false` 的每一条都有非空 `reason`
- [ ] `include: true` 的每一条 `reading/pos/meaning/translation/a_note` 都非空
- [ ] `reading` 是纯平假名（`ー` 与 `・` 允许），无汉字、无标签
- [ ] `pos` 在允许集合内
- [ ] `a_note` 以 `<p>` 开头，`<p>` 配对，`<ruby>/<rt>` 配对
- [ ] `a_note` 含「中文翻译」「核心词汇」「语法要点」三段
- [ ] `a_note` 里日语汉字的 ruby 齐全（送假名在 `<rt>` 外），中文汉字一个都没标
- [ ] 全文无 `\`、无 `$`、无半角 `"`、无 `**`、无代码围栏
- [ ] 只用了 `<p> <br> <b> <ruby> <rt>`

> 可自动化程度：第 1–3、6、8、9 条脚本可查；「ruby 覆盖是否正确」「词形还原是否合理」
> 只能靠语义判断。参考实现见 `code/common/check_mine.py`。

---

## 8. 异常处理

| 情况 | 处理 |
|---|---|
| 候选是碎片，还原不出确切词 | `include: false`，`reason` 写「碎片，无法还原成具体词」 |
| 读音不确定（生僻汉字、人名） | 判 `false`（人名）或 `reading` 留空 —— 但留空会导致自检不合格，**优先判 `false`** |
| 无法判断是生词还是专有名词 | 判 `false`（宁可漏收，不要给牌组塞人名）并把 `word` 列进汇报的「判断不了」清单 |
| 同一条输入里 `occurrences` 有多个句子 | 用**第一条**（`occurrences[0]`）的 `sentence` 做翻译和讲解 |

## 附录 · 一条完整样例

**输入**

```json
{"word": "漕ぐ", "count": 1, "scripts": "kanji", "len": 2,
 "occurrences": [{"noteId": 1759000000001,
   "sentence": "えっと これが私が考えた ゴンドラを揺らさないように 漕ぐ練習で… 揺れまくってますけど",
   "sentence_html": "えっと これが<ruby>私<rt>わたし</rt></ruby>が<ruby>考<rt>かんが</rt></ruby>えた ゴンドラを<ruby>揺<rt>ゆ</rt></ruby>らさないように <ruby>漕<rt>こ</rt></ruby>ぐ<ruby>練習<rt>れんしゅう</rt></ruby>で… <ruby>揺<rt>ゆ</rt></ruby>れまくってますけど",
   "source": "Aria The Animation 04.jp.srt"}]}
```

**输出**

```json
{"word": "漕ぐ", "reading": "こぐ", "pos": "他动词",
 "meaning": "划（船）、摇（橹）",
 "translation": "呃，这是我为了不让凤尾船摇晃而练的划船方法……虽然摇得厉害就是了。",
 "a_note": "<p><b>中文翻译：</b>呃，这是我为了不让凤尾船摇晃而练的划船方法……虽然摇得厉害就是了。</p><p><b>核心词汇：</b><br><ruby>漕<rt>こ</rt></ruby>ぐ：他动词（五段）。划船、摇橹。<br><ruby>揺<rt>ゆ</rt></ruby>れる：自动词（一段）。摇晃、晃动。</p><p><b>语法要点：</b><br>〜ないように：表示「为了不……」，接在动词ない形后，提示目的。此处「揺らさないように漕ぐ」＝为了不让它晃而划。</p><p><b>动词变形解析：</b><br><ruby>漕<rt>こ</rt></ruby>ぐ（原形）→ <ruby>漕<rt>こ</rt></ruby>ぎ（連用形）→ 漕ぎます（ます形）</p>",
 "include": true, "reason": ""}
```
