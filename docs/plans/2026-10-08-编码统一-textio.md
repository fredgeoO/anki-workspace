## 1. 目标与成功标准

**目标**：把「GBK 解码/输出」这一类问题一次解决 —— 一个唯一实现放在 `code/common`，
所有脚本复用它，以后新脚本抄一行就行；外加一条防回退的审计。

**成功标准**

1. 常跑链路里任何一个脚本，打印中日文/♪/全角符号都不再 `UnicodeEncodeError`，也不再静默乱码。
2. `sys.stdout.reconfigure(...)` / `io.TextIOWrapper(sys.stdout...)` 这类手工补丁在全仓**归零**，
   唯一实现是 `code/common/textio.py`。
3. 所有**会直接跑的脚本**（有 `if __name__`，或在模块层直接 `print(...)`）都有那一行 `import textio`；
   `python code/common/textio.py audit --strict` 退出码 0。
4. 读文件不再靠「默认编码」：UTF-8 / UTF-8-BOM / UTF-16(PS 的 `Out-File`) / GBK / CP932 都能读，
   **不是 UTF-8 时会在 stderr 出声**（静默乱码正是这次误删的帮凶）。
5. **行为不变**：各脚本 CLI、stdout 契约、退出码、`--commit` 演练闸门、产物格式一字不改。
6. PowerShell 侧有同等地位的补丁：读工作区文件默认按 UTF-8（`ps-utf8.ps1`），
   并在文档里写明「判断 / 筛选 / 删除前的确认交给 Python」。

| 事实 | 实测值 |
|---|---|
| shell | **Windows PowerShell 5.1.22621.4249**（`PSEdition=Desktop`，`$PSHOME` 是 `v1.0`） |
| 代码页 | `chcp` = **936**；`[Console]::InputEncoding` = gb2312 |
| DSH 已做的补救 | `$OutputEncoding` = utf-8、`[Console]::OutputEncoding` = utf-8（**都不管 `Get-Content` 读文件**） |
| Python 侧 | stdout 是管道时 `sys.stdout.encoding` = **gbk**（`locale.getpreferredencoding()`） |

| PS 5.1 读脚本文件 | **无 BOM 的 .ps1 按 ANSI 解析** —— 中文注释会被解成乱码、可能直接把语法搞坏（实测报「意外的标记 }」） |
| `$PROFILE` | 四个位置**都不存在** |

四个炸点，一次实测：

```powershell
# ① 输出：GBK 编不出的字符直接崩
& $PY -c "print('日本語テスト ♪ 平家物語')"
#   UnicodeEncodeError: 'gbk' codec can't encode character '\u266a' in position 7

# ② 输出：GBK 编得出来的汉字不崩，但消费方（UTF-8）看到乱码
& $PY -c "import sys; d=sys.stdin.buffer.read(); print(d.decode('utf-8'))"   # 管道喂 UTF-8
#   '�ձ��Z�Υѥ���'      ← 先把文本编成 GBK 字节，再被当 UTF-8 解

# ③ 读文件：open(path) 不带 encoding 时用 GBK（locale）

# ④ 子进程：subprocess.run(..., text=True) 不带 encoding 时同样按 GBK 解子进程输出
```

**事故现场**（用一个假的 cmp 产出复现，§7 有命令）：

```powershell
$o = Get-Content cmp_out.json -Raw | ConvertFrom-Json
#   ConvertFrom-Json : 传入的对象无效，应为“:”或“}”。
#   (11): {"鎸亣鍚?: "銇点倞銇屻仾", "璇?: "寰瑰", "渚嬪彞": "…"}
$o.振假名          # → $null     ← 字段名已经被解成乱码
-not $o.振假名     # → True      ← 「字段为空就删」的判据对**每一个**文件都成立
```

`ConvertFrom-Json` 抛错 → `$o` 是 `$null` → 按字段名取属性一律 `$null` → 判断恒真 →
`output/cmp4` 的 39 个产出被删。**根因不是 JSON，是 5.1 的 `Get-Content` 默认 ANSI=GBK。**

## 3. 设计

### 3.1 `code/common/textio.py`（唯一实现）

命名对齐既有约定（`paths` 管路径、`anki_api` 管 Anki 访问、`textio` 管文本 I/O 与编码）。

```python
import textio as T          # ← import 这一下就把 stdio 接管成 UTF-8（幂等，失败不抛）

T.setup()                   # 显式再接管一次（幂等）；返回每流的 (before, after)
T.info()                    # 当前编码/环境快照（info / check CLI 用它）

T.read_text(p)              # 自动判 UTF-8/BOM/UTF-16/GBK/CP932；非 UTF-8 → stderr 警告
T.read_text_ex(p)           # -> (text, encoding, lossy)
T.load_json(p)              # 带 BOM 也读得进（json.load(open(p, encoding='utf-8')) 读不进）
T.read_stdin()              # PowerShell 管道（UTF-8 或 GBK 都收），走 sys.stdin.buffer
T.loads_json(s) / T.dump_json(obj, p) / T.write_text(p, text)     # 一律 UTF-8 无 BOM、LF
T.run(cmd)                  # subprocess：text + utf-8 + 把 PYTHONIOENCODING 传给子进程
T.child_env() / T.text_kwargs()
```

**判定顺序**（`decode()`）：BOM → **UTF-8 严格**（最强证据，一票采信）→ 有 NUL 时试 UTF-16 →
其余候选严格试解后按「像不像正常中日文正文」打分取最高 → 全失败才按 `errors` 有损解码（绝不抛）。

打分 `_plausibility()`：假名权重最高（日语正文一半是假名），汉字次之；UTF-8 乱码标志字
（`繧縺譁繝`）、替换字符、半角片假名都扣分 —— 因为 `cp932` 与 `gb18030` 都能「吃下」几乎
任意字节，只看「解得出/解不出」会猜错。

### 3.2 CLI（体检 / 安全读 / 防回退）

```powershell
& $PY code\common\textio.py check                 # 15 项自检：stdio / 子进程管道 / 六种编码的文件 / BOM JSON / 警告 / ps 文件带 BOM
& $PY code\common\textio.py info                  # 当前 stdio 与环境（排查乱码第一步）
& $PY code\common\textio.py read x.json --keys 振假名,词   # 安全读（替代 PS 的 Get-Content|ConvertFrom-Json）
& $PY code\common\textio.py decode weird.srt --head 3      # 这个文件是什么编码、有没有损失
& $PY code\common\textio.py audit --strict        # 0 = 干净（5 条规则见下）
```

`audit` 五条规则（**只扫代码**，用 `tokenize` 把注释/docstring 整行屏蔽，所以文档里引用旧写法不算回退；
写 `textio-ok` 的行一律豁免）：

| 规则 | 内容 | 是否致命 |
|---|---|---|
| R1 | 手工编码补丁：`stdout.reconfigure(` / `TextIOWrapper(sys.stdout` / `stdio.encoding =` / `PYTHONIOENCODING='…'` | ✗ 致命 |
| R2 | 入口脚本（有 `if __name__`）没有 `import textio` | ✗ 致命 |
| R3 | 文本模式 `open()` / `Path.read_text()` 没写 `encoding`（二进制 `'wb'` 与自己带编码策略的接收者不算） | · 建议 |
| R4 | `.ps1` 里 `Get-Content` / `Import-Csv` / `ConvertFrom-Json` 等没钉编码（注释、已带 `-Encoding`、`$PSDefaultParameterValues['Get-Content:Encoding']` 豁免） | · 建议 |
| R5 | 直接用 `sys.stdin.read()`（建议 `T.read_stdin()`） | · 建议 |

### 3.3 `code/common/ps-utf8.ps1`（PowerShell 侧另一半）

DSH 已经设好 `$OutputEncoding` 和 `[Console]::OutputEncoding`，**但这两个都不管 `Get-Content` 读文件**，
5.1 也没有 `utf8NoBOM`。补丁做的事：

```powershell
# 推荐：读内容再执行 —— CurrentUser 策略是 RemoteSigned，未签名 .ps1 会被拦
iex ([IO.File]::ReadAllText("$WS\code\common\ps-utf8.ps1", [Text.Encoding]::UTF8))

# 或者：只放开当前进程再 dot-source（不需要管理员）
Set-ExecutionPolicy -Scope Process Bypass -Force; . "$WS\code\common\ps-utf8.ps1"
```

* `$PSDefaultParameterValues` 把 `Get-Content` / `Set-Content` / `Add-Content` / `Out-File` /
  `Import-Csv` / `Export-Csv` / `Select-String` 的默认编码钉成 `utf8`；
* `$OutputEncoding` / `[Console]::OutputEncoding` / `[Console]::InputEncoding` 设成 **无 BOM 的 UTF-8**；
* `$env:PYTHONIOENCODING='utf-8'` + `$env:PYTHONUTF8='1'` —— 连 `python -c "…"` 这种一行也一起修；
* 附一个 `Read-JsonFile`（`[IO.File]::ReadAllText($p, UTF8) | ConvertFrom-Json`）当安全读的名字。

**这个文件必须存成 UTF-8 带 BOM**（PS 5.1 对无 BOM 脚本按 ANSI 解析，中文注释会毁掉语法；
`textio.py check` 与 `audit` 的 R4 都会断言/抓这一条）。

**不替代 Python 侧**：它只让 PS 不再读错，**判断/筛选/删除的确认仍应交给 Python**（`textio.py read` + 先打印清单）。

## 4. 迁移设计（`code/oneshot/migrate_textio.py`）

* 默认**演练**，`--commit` 才落盘（铁律 1）；幂等，可反复跑。
* 认四种手工写法并整块替换成一行 `import textio`：裸 `reconfigure` 行、`if hasattr(...)` 护栏块、
  `try/except: pass` 包裹块、`io.TextIOWrapper(sys.stdout...)` 赋值。
* 给**所有入口脚本**补那一行；文件里没有 `code/common` 在 `sys.path` 上时，顺带补最小路径引导
  （`_TEXTIO_HERE` + `os.path.join(..., '..', 'code', 'common')`），缺 `os`/`sys` 就一起补。
* **两道闸门**：改动后先 `ast.parse`，语法不过就不落盘；`--commit` 后再逐个 `py_compile`。
* 语义点（`read_stdin` / `read_text` / stdin 消费处）由人手改，迁移器只做机械部分。

### 5.3 迁移过程中发现并修掉的问题（都是闸门抓出来的）

1. **引导块少了换行** → 三行粘成一行、`ast.parse` 直接报 invalid syntax。闸门拦下，修 `bootstrap_lines()`。
2. **锚点匹配到函数体里的 `import local_llm`** → 会把顶格 import 塞进函数体。改成只看顶格的
   import / `sys.path` 行。
3. **`imported_roots()` 用了 `ast.walk`** → 函数体里的 `import sys` 骗过了检查，`srt.py` 的引导块
   里出现 `sys.path.insert` 却没有顶层 `import sys`。改成只看 `tree.body`，并给 `srt.py` 补 `import sys`。
   （全仓复查：只有这一个文件受影响。）
4. **`try:` / `except Exception:  # noqa`** 的尾部注释让 `except` 正则不匹配 → 会留下空 `try` 块。
   `anki_api.py`、`today_weak.py`、`find_grammar.py`、`preflight.py` 都属这类，修正则后整块替换。
5. **审计一跑就崩**：R2 的条目是字符串、别的规则是 `(行号, 原因)`，`show()` 解包炸了
   （现树 R2 是 0 才没暴露）—— 拿备份树跑「迁移前」时被抓出来。
6. **审计误报**（为了让 `--strict` 真能当闸门，逐个修）：docstring 里的旧写法（`tokenize` 整行屏蔽）、
   `open(dest, 'wb')` 二进制写、`def open(cls, …)` 定义、`srt_mod.read_text(p)` 这种自带编码策略的接收者、
   PS 注释行、`$PSDefaultParameterValues['Get-Content:Encoding']`（含 `:Encoding` 不是 `-Encoding`）。
7. **执行策略拦住 dot-source**：`CurrentUser = RemoteSigned`，`ps-utf8.ps1` 是未签名脚本 →
   「未对文件进行数字签名」直接失败（我第一次验证时就撞上了）。改用
   `iex ([IO.File]::ReadAllText(<file>, [Text.Encoding]::UTF8))` 读内容执行，或在当前进程
   `Set-ExecutionPolicy -Scope Process Bypass -Force` 后再 dot-source；两条路径都已实测通过。
8. **无 BOM 的 .ps1 被当 ANSI 读**：PS 5.1 解析脚本文件时，没有 BOM 就按 ANSI(GBK) 解码，
   中文注释被解成乱码后可能吞掉花括号（实测报「意外的标记 }」，位在函数结束的 `}`）。
   修法：`ps-utf8.ps1` 用 `textio.write_text(..., bom=True)` 重写成 **UTF-8 带 BOM**；
   并在 `check`（断言带 BOM）与 `audit` R4（无 BOM 即报）两处加了守卫 —— 用一份去掉 BOM 的副本
   验证过审计确实抓得到。
9. **第一轮的判据太窄，漏了 44 个顶层脚本**（最重要的一条）。第一版规则是「有 `if __name__` 的入口脚本」，
   于是 `core6000-analysis/*.py`（9 个）与 `code/analysis/anki_analyze/*.py`（20 个）这类
   **没有 `__main__`、跑到顶层就打印**的脚本一个都没迁移 —— 实测在没设 `PYTHONIOENCODING` 的干净环境里
   `core6000-analysis\analyze.py` 照样打出 `1. ��������`（GBK 乱码）。
   修法：判据改成 `textio.needs_textio(src)`（**有 `if __name__` 或模块层直接 `print(...)` /
   `sys.stdout.write(...)`**，用 ast 判定），迁移器与 `audit` R2 共用这一个函数；补跑一轮 44 个文件，
   顶层脚本从此全覆盖。A/B 证据见 §6.4。
10. **工具链会把 BOM 抹掉**：`ps-utf8.ps1` 用 write/edit 改过一次之后 BOM 就丢了
    （check 立刻报 `✗ ps-utf8.ps1 存成 UTF-8 带 BOM`）—— 改这个文件之后必须补回来：
    `T.write_text(p, T.read_text(p), bom=True)`。这也是把「BOM 断言」放进 `check` 的价值。
11. **沙箱里 `.ps1` 文件跑不了、profile 也不加载**（见 §8-2）：受限令牌下 Restricted / AllSigned /
    RemoteSigned 一律拦（"is not digitally signed"），`Unrestricted` 报
    `AuthorizationManager check failed`，**只有 `Bypass` 能跑**；`$PROFILE` 装好后在新会话里实测
    `$PSDefaultParameterValues` 仍为空。所以 DSH 会话里只有 `iex` 一条路，
    ad-hoc python 用 `-X utf8`（两者都已实测通过）。

### 5.4 手改的语义点

* `newwords.read_stdin()`、`cover_cli.py --stdin`、本地模型 `llm.py -i -`（两处）：改走 `textio.read_stdin()`。
* `vocab_cover/srt.py:read_text()`：改走 `textio.read_text(path, encodings=ENCODINGS)`，
  字幕专用候选表保留（`utf-8-sig, utf-8, cp932, shift_jis, euc_jp, gb18030`），
  原来那段「`繧` 系乱码就换下一个编码」的经验并进了 `_plausibility()`。
* `filter_subtitle.py:read_text()`：改走 `textio.decode(raw, encodings=('utf-8',), errors='strict')`，
  **保持原来的严格语义**（不是 UTF-8 就报错，不静默替换）。
* `find_grammar.py` 文档串里的 `$env:PYTHONIOENCODING='utf-8'; python …` 改成
  「stdio 由 `code/common/textio.py` 接管」。
* 清掉因此变成死引用的 `import io`（`make_weak_list.py`）与 `import locale`（`newwords.py`）。

### 5.5 与计划的偏离

* 计划只写「迁移 + 文档」；实际多做了 **静态引导路径校验**（61 个文件逐个解析 `_TEXTIO_HERE` 指向）
  与 **改动后 `ast.parse` 闸门** —— 上面第 1、2、4 条 bug 全靠它拦住。
* 审计从 3 条规则扩到 5 条，并加了「只扫代码」的屏蔽，否则 `--strict` 会被文档和二进制写误报撑成噪声。
* **判据从「有 `if __name__`」扩到「会直接跑」（§5.3-⑨），补跑第二轮 44 个顶层脚本** ——
  这是事后复查 `core6000-analysis/analyze.py` 的乱码输出才发现的，说明「一次过」必须按
  「会不会真的执行并打印」来判断，而不是按文件长相。

## 8. 边界与遗留

1. **EUC-JP 分不开 GB18030**：GB2312 抄了 JIS 的假名行，`日本語の字幕です。` ↔ `泣塑胳の机穗です。`
   的假名/汉字计数一模一样，只靠字符分布无法判定。所以自动候选表**故意不含 `euc_jp`**：
   老字幕要显式 hint（`textio.read_text(p, encodings=srt.ENCODINGS)` —— `srt.py` 已经这么做）；
   无 hint 时**不会丢字**（不是有损解码），但汉字可能是 GBK 读法。已在 `check` 里作为已知边界断言。
2. **PowerShell 侧要手动加载**（三重限制叠加）：受限令牌下 `.ps1` 文件**根本跑不了**
   （Restricted / AllSigned / RemoteSigned 都拦，`Unrestricted` 报 `AuthorizationManager check failed`，
   只有 `Bypass` 行），且沙箱 shell **不加载 `$PROFILE`**（已实测）。所以 DSH 会话里：
   `iex ([IO.File]::ReadAllText("$WS\code\common\ps-utf8.ps1", [Text.Encoding]::UTF8))`；
   ad-hoc 的 `python -c` 加 `-X utf8`。
   `$PROFILE` 已在 2026-10-08 装好（UTF-8 带 BOM，内容是「Test-Path + iex」），
   **只对你自己的 PowerShell 窗口生效** —— 想连 DSH 会话也自动生效，得等 DSH 用 `Bypass`
   或非受限令牌跑 shell（做不到就从文档规则上兜住，见 README §6 第 8 条）。
3. **机器级 skill 副本没打补丁**：`~/.dsh/skills/local-llm/scripts/llm.py` 与工作区副本同源，
   但它在工作区外；`README` 与技能里写的是 `$env:DSH_HOME\skills\local-llm\scripts\llm.py`。
   同样需要批准才能改。
4. **ad-hoc 的 `python -c` / 一次性脚本**不经过 `import textio`，只靠 `ps-utf8.ps1` 设的
   `$env:PYTHONIOENCODING/PYTHONUTF8`；没 dot-source 且没设 env 时仍会 `UnicodeEncodeError`（预期行为，
   不再靠改环境变量兜底）。
5. **工作区没有 git**，一切「回退」都靠备份目录；`data/evidence/textio_migration_backup/` 建议留一段时间。
6. `core6000-analysis/` 是「与 code/ 互不依赖」的独立子项目，这次为它补了一行 `code/common` 引导
   （coupling +1）—— 换来的是它的分析脚本也不再因 GBK 崩。要退回只需删那三行。
