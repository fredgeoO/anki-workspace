# 日语例句卡生成 · Agent 执行指令

> 状态：active ｜ 最后核实：2026-10-24

**这是什么**：阶段二子代理的执行规范 —— 把 `Sentence` 原文生成 `AINote`（讲解）与
`Sentence HTML`（带振假名的例句）。
**为什么存在**：把语义活交出去时，输出形状与硬规则必须写死，否则校验必挂。
**什么时候读**：要给例句卡生成这两个字段时 —— `cards.py gen` 的默认路径用它当规范，
本地模型不可用时我自己按它写、再用 `cards.py write` 收口。

> **相关文档**：[pipeline-guide.md](pipeline-guide.md)（阶段一/三/四的操作手册）、
> [mine-agent-instruction.md](mine-agent-instruction.md)（阶段四：从这些例句里挖**生词卡**的规范）。
> 本文件只管**整句**的讲解与振假名；挖单词是另一份规范、另一套字段。

## 0. 角色

你是一名精通日语的语言学教授，同时是一个能操作 Anki 的 agent。你自己取卡、自己生成、自己写库、自己自检，**不输出 JSON 包装，不要求人类复制粘贴**。

## 1. 输入契约

从 Anki 读取，**只读不改**以下字段：

| 字段 | 用途 |
|---|---|
| `Sentence` | 主输入。待讲解的日语句子。可能含 `<br>`（字幕两行） |
| `Source` | 出处（文件名 + 时间码），用于判断语域（动画口语 / 新闻报道 / 纪录片旁白） |
| `Word` | 若已有值，说明该卡已指定重点词，**核心词汇必须以它为首条** |
| `Image` / `Sentence Audio` / `URL` | 仅供理解语境，不要写入 |

## 2. 输出契约

只写两个字段，其余字段一律不动：

| 生成的 Key | 写入字段名（注意大小写与空格） |
|---|---|
| `AI_Note` | `AINote` |
| `Html` | `Sentence HTML` |

写入方式：调用 `updateNoteFields`，`fields` 里**只放这两个键**。绝不整字段覆盖，绝不传 `Image` / `Sentence Audio` / `URL` / `Source`。

若处于"只生成不写库"的批处理模式，则按下面这种**纯文本分块**返回，不要 JSON、不要代码围栏：

```
<<<AINote>>>
（AINote 的 HTML）
<<<SentenceHTML>>>
（Sentence HTML 的 HTML）
```

## 3. 硬约束（违反任何一条即为不合格）

1. **禁止 LaTeX**：不出现 `$...$`、`\rightarrow`、`\to` 等。推导一律用全角箭头 **→**（U+2192）。
   历史批次里出过两类残渣——`$\rightarrow$` 的 `\r` 被当成回车吃掉，留下 `$ightarrow$`；
   `$\text{原形}$` 的 `\t` 被吃成制表符，留下 `$<TAB>ext{原形}$`。两者都已批量清理，
   体检与修复入口见 `code/oneshot/verify_no_residue.py`（只读审计）、
   `code/oneshot/fix_bad_arrow.py` 与 `code/oneshot/fix_text_wrap.py`（默认演练，`--commit` 才写库）。
2. **禁止反斜杠 `\`**：字段值里不允许出现 `\`。需要引号时用「」或“”，**不要用 `\"`**——HTML 里 `\"` 会显示成反斜杠加引号。
3. **字段值内禁止半角双引号 `"`**；万不得已用 `&quot;`。
4. **禁止 Markdown**：不要 ```` ``` ````、不要 `**加粗**`，排版只用 HTML 标签。
5. **只用标签白名单**：`<p>` `<br>` `<b>` `<ruby>` `<rt>`。禁止 `<div>` `<span>` `<style>` `<table>` 以及任何 `class=` / `style=` 属性。
6. **日语汉字必须标 ruby；中文汉字绝对不标**。判断标准：出现在日语例句、日语词汇、日语推导里的汉字要标；出现在中文翻译、中文释义里的汉字不标。
   **纯假名不加 ruby**：`なる`、`と`、`ある` 这类没有汉字的词不要造 `<ruby>と<rt>と</rt></ruby>` 这种标注——旧卡里出现过，是噪声，不要沿用。
   **敬语接头辞 `お` / `ご` 放在 `<ruby>` 之外**：正确 `<ruby>墓<rt>はか</rt></ruby>` 前面单写 `お`，即 `お<ruby>墓<rt>はか</rt></ruby>`；不要写 `<ruby>お墓<rt>おはか</rt></ruby>`。
   **同一汉字在不同活用形下读音不同时，各按实际读音标注**：`<ruby>来<rt>く</rt></ruby>る` / `<ruby>来<rt>き</rt></ruby>た`，这不是不一致。
7. **送假名放在 `<ruby>` 之外**：
   - 正确：`<ruby>食<rt>た</rt></ruby>べる`、`<ruby>届<rt>とど</rt></ruby>ける`
   - 错误：`<ruby>食べる<rt>たべる</rt></ruby>`
   - 熟字训整体标：`<ruby>今日<rt>きょう</rt></ruby>`、`<ruby>郵便局<rt>ゆうびんきょく</rt></ruby>`
8. **不得改动例句本身**：不增删词、不改标点、不改空格、不改 `<br>` 位置。

## 4. `AINote` 结构规范

固定四段，按顺序，每段一个 `<p>`。**第 4 段按需出现，不要为了凑格式硬编。**

```html
<p><b>中文翻译：</b>自然流畅、符合语境的中文翻译。</p>
<p><b>核心词汇：</b><br>词条1<br>词条2<br>词条3</p>
<p><b>语法要点：</b><br>句型1：含义 + 接续 + 功能<br>句型2：……</p>
<p><b>动词变形解析：</b><br>推导1<br>推导2</p>
```

**核心词汇**每条形如 `<ruby>漢字<rt>かな</rt></ruby>：词性。中文释义。（外来语附源词）`

- 只列**句中出现过**的词，2–5 个，不要堆词典。
- 必须是**本句里的那个词形**：句中是「あの子」，就不要写成「子ども」；词典形对活用形
  （送る → 送った）可以，但不许拿上位词/近义词顶替（2026-10-24 复审）。
- 优先级：`Word` 字段指定的词 ＞ 惯用搭配／熟语 ＞ オノマトペ ＞ 片假名外来语 ＞ 一般实词（N4 以上）。
- 词性用：名词／イ形容词／ナ形容词／自动词／他动词／副词／接续词／惯用句。
- 若该卡是"无学习内容"的短句（纯寒暄、纯语气），不要强行凑词汇，直接走第 8 节。

**语法要点**每条给出：句型 → 含义 → 接续（如"接在动词た形后"）→ 在句中的具体功能。句中只出现一个句型就只写一个。
每条都要**写完整**（不要停在「…」「「」），也不要自相矛盾：`にちがいない` 是「一定是～」，
不能写成「觉得一定是～」（既"觉得"又"一定"）。

**动词变形解析**格式统一为：`原形 → 变形1（变形名称） → 变形2（变形名称） + 辅助词/尾缀`

- 只写句子里**真实存在**的活用。全句没有活用动词（如名词句、形容词句、连体形未发生音变的句子）时，省略整段。
- 例：`調べる（原形）→ 調べて（て形）＋みる → 調べてみる（〜てみる：试着做）`
- **本段出现的日语汉字同样必须标 ruby**（已核对：旧卡 77 张含此段的卡里有 69 张都标了），例如 `<ruby>戻<rt>もど</rt></ruby>る → <ruby>戻<rt>もど</rt></ruby>った`。

**长度克制**：每段 1–3 句，整段 `AINote` 控制在约 400 字以内。这是复习卡，不是词条页。

## 5. `Sentence HTML` 结构规范

只含**例句本身**的 HTML，不含翻译、不含解释、不含标点补充。

```html
<ruby>郵便局<rt>ゆうびんきょく</rt></ruby>に<ruby>戻<rt>もど</rt></ruby>った<ruby>時<rt>とき</rt></ruby>に<ruby>調<rt>しら</rt></ruby>べてみるよ
```

- 原文有 `<br>` 的，原位置保留单个 `<br>`（不要写成 `<br><br>`）。
- 不要用 `<p>` 包裹，不要加句末标点。

**文本一致性（最重要的一条）**：比对时必须**先整块删除所有 `<rt>…</rt>`（连同其中的假名）**，再剥掉其余标签；此时结果必须与 `Sentence` 字段**逐字相同**（含空格、含 `　` 全角空格、含原有标点）。

⚠️ 不要"直接剥掉所有标签再比对"——那样 `<rt>` 里的假名会被算进文本，永远比对不上。这是最容易写错的一步。

## 6. 生成方式（固定的是方法，不是流程）

**没有规定的批次、顺序或流水线。** 一次处理一张、三张还是三十张，由调用方决定；
本规范只固定「输入什么、输出什么、怎么判合格」。

1. **取卡**：指定 noteId / 查询 / 文件，读 `Sentence` / `Word` / `Source` 三个字段。
   读什么由调用方点名，不要求先切批。
2. **产出两个字段值**：
   - 原子入口：`python code/execution/cards.py gen`（本地模型直连）或
     `cards.py write --file`（现成 JSON，同一套 repair + 闸门）。
     `Sentence HTML` 由 `ruby_engine` 拿**原始 `Sentence` 当骨架**重渲染，
     不依赖模型一次写对。
   - 整集批量：`pipeline.py split/gen/write` 或 `cli.py episode` 只是**调用方**；
     它们复用同一份提示词（`pipeline.LOCAL_INSTRUCTION`）与同一套 repair/闸门，
     不构成本规范的额外步骤。
3. **写库**：`updateNoteFields`，`fields` 只含 `AINote` 与 `Sentence HTML`；写完回读。
4. **校验只做一次，且由脚本做**：`cards.py` / `pipeline.py gen` 内部用 `check_cards` 机械判一次。
   `AINote` 侧不合格**只重问那一轮**；`Sentence HTML` 侧的机械问题**不重问**，
   交给 `ruby_engine.repair` 重渲染。仍不合格的按第 8 节两个字段留空。
   **生成方不要自己跑自检脚本、更不要“跑到 0 不合格”** —— 那是把同一份校验算两遍，
   还会把一批 14 张拖成小时级返工。改不掉的（例如读音确实定不下来）留着、在汇报里列出即可。
5. **报告**：输出 `成功 N / 跳过 M / 待人工 K`，并列出待人工的 noteId 与原因。

**幂等**：默认只处理 `AINote` 为空的卡；`AINote` 已有内容则跳过，除非人类明确说"覆盖"。
原子入口 `cards.py` 更保守：任一目标字段已非空就跳过（并打印是哪个字段），`--overwrite` 才重做。

**去重口径（查重用 `Sentence`，不用 `AINote`）**：判断"这句例句是不是已经有过卡"时，**唯一依据是 `Sentence` 字段**，与 `AINote` 是否为空、内容写了什么**无关**。

- 比对前归一化：NFKC 统一全角/半角 → 整块删 `<rt>…</rt>` → 剥其余标签 → 去掉全部空白（含全角空格 `　`）。**标点保留**，`ありがとう` 与 `ありがとう！` 不算重复。
- 参照集合是 **本 deck（乃至全库）所有卡的 `Sentence`**，包含 `AINote` 尚为空的卡。
- 同一批里两张卡 `Sentence` 相同，同样算重复。
- ⚠️ 反面写法：用 `AINote:_*` 拉一批"已处理的卡"当参照系去查重。这会漏掉 `AINote` 还没生成的卡（未跑的批次、被 suspend 的弃用卡），把重复例句放进队列。

`AINote` 只有两个用途，都与查重无关：① 幂等判据（这张卡跑没跑过 prompt）；② 待办队列查询（`AINote:` / `AINote:_*` 见第 9 节）。

## 7. 自检清单

- [ ] 剥标签后与 `Sentence` 原文逐字一致（含空格与 `<br>` 位置）
  → 比对口径：先删 `<rt>…</rt>` 整块，再剥其余标签
- [ ] 全文无 `\`、无 `$`
- [ ] 无 Markdown 代码围栏、无 `**`
- [ ] 无半角 `"`
- [ ] 只用了 `<p> <br> <b> <ruby> <rt>`，且 ruby/rt 标签配对
- [ ] 日语汉字全部有 ruby，中文汉字一个都没标
- [ ] 没有给纯假名加 ruby
- [ ] 送假名在 `<rt>` 之外
- [ ] `Sentence HTML` 里不存在任何 `ruby` 之外的汉字（这一条可完全自动化校验）
- [ ] `AINote` 至少有「中文翻译」「核心词汇」两段
- [ ] 变形解析段只写了句中真实存在的活用，且该段日语汉字也标了 ruby
- [ ] 写入的字段名正确：`AINote`、`Sentence HTML`
- [ ] 查重只比 `Sentence`（归一化后），没有拿 `AINote` 是否为空当去重依据

> 可自动化程度：`Sentence HTML` 的全部规则都能脚本化校验；`AINote` 里中文解释与日语词混排，ruby 覆盖只能靠语义判断，脚本只能校验结构（段落齐全、标签白名单、标签配对、非法字符）。
> 参考实现见 `code/common/check_cards.py`。

## 8. 异常处理

判据的分界线是**残余部分还能不能讲**，不是"句子完不完整"。

| 情况 | 处理 |
|---|---|
| 只有**真正无法给出可靠讲解**时才算异常：文字明显错误或乱码、关键读音无法确定且无法回避、整句没有可解释的语义单位 | `AINote` 与 `Sentence HTML` **两个字段都留空**，不做任何写入，把 noteId 计入"已跳过"并汇报给人类。这样该卡仍留在"未处理"队列里，人类可以手动处置 |
| 句子被字幕切断、残余部分**仍有可讲内容**（例如结尾停在「って」「のに」「けど」，但前半段有可讲的词或句型） | **正常生成**，并在「语法要点」末尾注明"主句被字幕省略"。不要标记为异常 |
| 读音不确定（人名、生僻汉字） | 不猜。该词不加 ruby 并在汇报中列出；其余内容照常生成 |
| 无法确定词性 | 省略词性，只写中文释义 |

> 为什么跳过时两个字段都留空、而不是写一个「待人工处理」标记：留空能让该卡继续被 `AINote:` 这类查询命中，不会被误当成已完成；写标记则会让它从待办队列里消失。
> 若确实要写显式标记（例如交给别人处理），`AINote` 写 `<p><b>待人工处理：</b>原因</p>` 且 `Sentence HTML` 留空——校验器 `check_cards.py` 对这一组合是豁免的。

## 10. 与旧提示词的差异（已修正的点）

| 旧写法 | 新写法 | 原因 |
|---|---|---|
| 输出纯 JSON，两个 Key | 直接写 `AINote` / `Sentence HTML` 字段 | agent 场景不需要解析层；省一次人工复制 |
| 双引号用 `\"` 转义 | 禁止出现半角引号，需要时用「」 | `\"` 是 JSON 层的要求；写进 HTML 字段会显示成 `\"` |
| "所有日语汉字必须 ruby" | 补充：送假名在 `<rt>` 外、熟字训整体标 | 原表述会导致 `<ruby>食べる<rt>たべる</rt></ruby>` 这种错标 |
| 四段固定 | 第 4 段按需出现 | 名词句、形容词句没有活用动词可推导 |
| 无异常条款 | 新增第 8 节 | 字幕残句会被编造出假的语法解释 |
| 无一致性要求 | 新增"剥标签后与原文逐字一致" | 文字与音频对不上，卡片就废了 |

## 11. 与 deck 内已有 92 张卡的样式差异（实测）

这 92 张卡并非统一格式，目前至少有 4 种写法。新规范的定位是"向其中较干净的那一支靠拢"：

| 写法 | 92 张中出现 | 新规范 |
|---|---|---|
| `AINote` 用 `<ul><li>` 列表 | 48 | 禁止（`<li>` 不在白名单） |
| `AINote` 用 `<h3>` 小标题 | 12 | 禁止 |
| `AINote` 用 `<span style=...>` | 4 | 禁止 |
| `AINote` 被 `<div>` 包裹 | 53 | 禁止 |
| `AINote` 已是 `<b>中文翻译：</b>` | 37 | ✅ 一致 |
| `AINote` 同时含 `<p>+<b>+<ruby>` | 49 | ✅ 一致 |
| `Sentence HTML` 为裸文本 | 62 | ✅ 一致 |
| `Sentence HTML` 被 `<p>`/`<div>` 包裹 | 30 | 禁止（要求裸文本） |
| `Sentence HTML` 用 `<br><br>` | 13 | 改为单个 `<br>` |

结论：跑完新 prompt 后，deck 会呈现"160 张新样式 + 92 张混合旧样式"。若要视觉统一，需要额外做一次旧卡标签规范化（只动标签、不动讲解文本），本指令不包含该步骤。

## 附录 A · 完整样例

**输入**

```
Sentence: 郵便局に戻った時に調べてみるよ
Source:   Aria The Animation 04.jp.srt (00h12m34.5s)
Word:     (空)
```

**AINote**

```html
<p><b>中文翻译：</b>回邮局的时候我查查看。</p>
<p><b>核心词汇：</b><br><ruby>郵便局<rt>ゆうびんきょく</rt></ruby>：名词。邮局。<br><ruby>戻<rt>もど</rt></ruby>る：自动词（五段）。返回、回到。<br><ruby>調<rt>しら</rt></ruby>べる：他动词（一段）。调查、查询。</p>
<p><b>语法要点：</b><br>〜た時に：表示"在……的时候"，接在动词た形后，提示后项动作发生的时间点。<br>〜てみる：表示"试着做某事"，接在动词て形后，带有尝试、不确定能否成功的语感。</p>
<p><b>动词变形解析：</b><br>戻る（原形）→ 戻っ（连用形·促音便）→ 戻った（た形）＋時に<br>調べる（原形）→ 調べて（て形）＋みる（原形）→ 調べてみる（〜てみる）＋よ</p>
```

**Sentence HTML**

