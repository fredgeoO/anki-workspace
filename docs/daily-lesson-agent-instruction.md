# 每日讲义 · 生成规范（说明与投放位置）

> 状态：active ｜ 最后核实：2026-10-25

> **这是一份说明文档，不是提示词。** 真正发给模型的规范在
> [`code/execution/lesson_local_prompt.md`](../code/execution/lesson_local_prompt.md)，
> 它是**唯一副本**——要改模型的教学口径，就改那个文件。
>
> 本文档解释那份规范**为什么长这样**、以及改它时要注意什么。
> 人的操作手册见 [`today_new-使用说明.md`](today_new-使用说明.md)。

---

## 一、它现在是怎么被送进模型的

2026-10 起，每日讲义改为**直连本地模型**（`code/execution/today_new.py gen`），
不再派子代理。投递方式：

```
POST http://127.0.0.1:8080/v1/responses                ← OpenAI Responses API（2026-10 切换）
  instructions         = lesson_local_prompt.md 全文    ← 规范，逐请求原样复用（NInfer 精确前缀缓存命中）
  input                = [{role: user, content: 当天这张卡的 JSON + 输出要求}]
                         ↑ 词汇卡的 JSON 自带 `dict`（plan 阶段预取的 JMdict 事实）
  reasoning            = {effort: none}                 ← 关掉思考链（NInfer 不认 chat_template_kwargs）
  max_output_tokens    = 4096                           ← 输出上限（旧名 max_tokens 不认）
  ※ 不发 text.format：NInfer 不支持结构化输出（json_object 会 400），JSON 形状靠提示词 + 解析重试
```

和子代理时代的关键差别：

| | 子代理时代 | 现在（直连） |
|---|---|---|
| 规范怎么到模型 | 模型**自己 Read 一遍**规范文档（每个子代理都要读） | 作为 **instructions** 直接发过去 |
| 额外的固定开销 | harness 系统提示词 + 工具目录（与日语教学无关） | 无 |
| 规范读几遍（10 张卡） | 10 遍 | 1 份内容，逐请求复用（NInfer 按精确前缀命中缓存，`cached_tokens` 会报） |
| 思考链 | 模型自己决定 | 强制关闭（实测 completion tokens 90 → 10） |

## 二、规范里为什么必须有这些内容

原来那份「子代理规范」的核心约束都保下来了，因为它们是**质量下限**，不是客套话：

1. **只输出一个 JSON 对象，不要围栏、不要开场白**——渲染器的解析虽然能兜一层，
   但闸门（逐张覆盖 + `teach` 非空）会连带失败。
2. **`entries` 逐张覆盖、键是 id**——缺一张 `merge` 就直接拒绝写讲义。
3. **`core` 不许照抄 Anki 释义**——释义是词典式的，照抄等于什么都没讲。
   学习者的讲义之所以有价值，在于「什么时候用它而不是它的近义词」。
4. **`examples` 必须自己造、且必须用上目标词**——
   抄卡片自带例句等于让他白读讲义；而不含目标词的例句是**实测最常见的模型错误**
   （本地 27B 会给「〜あまり」造出「節約しすぎて…」）。后者已经做成**机械可查**
   （`check_examples` + `gen` 的自动返工），不再只靠规范约束。
5. **`usage` / `uses` 每条都要带接续或搭配**——光说意思没用，语法卡尤其。
6. **语法卡的 `uses` 必须有一条反面**（什么时候不能用）——语法点的价值一半在反面。
7. **`structure` 要把脏接续表整理干净**——Anki 原始字段里有
   `（ 肯こう 定てい 形けいだけ）` 这种汉字夹注音的脏数据，直接渲染出来没法背。
8. **`memory` 禁止「多读多记」类废话**——要么给词源/汉字拆解，要么给具体场景。
9. **读音/词性/释义以卡片数据为准，不要编造**——模型不知道 ABS 导入时剥掉了字幕注音。
10. **`dict` 是预取好的词典事实，不是可选项**（2026-10-25 起）——`plan` 在发请求之前
    已把读音候选、词性、义项（英文 gloss）、语域、适用限制查好挂到卡上。模型按它定
    读音与义项，不再自己猜；释义与 `dict` 冲突时以 `dict` 为准。这条规则让「多义词取哪条」
    「读音歧义」有据可依，代价是每张词汇卡多几十到一百多 token（已在规范里写明只取前几条义项）。

## 三、改这份规范时的注意事项

- **改的是教学口径，不是格式。** 格式（字段名、JSON 结构）一改，就必须同步改
  `today_new.py` 里的 `render_teach` / `normalize_teach` / `check_examples`；
  只加字段的话，渲染器会自动忽略，不会报错。
- **规范变长 = 每个请求都变贵。** 它按请求重复发送（默认每请求 1 张卡），
  加 100 字的说明 = 10 张卡多花 10 次。
- **别在规范里写脚本路径。** 这段文本给模型读，`docs/...`、`output/...`
  这类路径对它没用，只会白烧 token（子代理时代需要，因为模型要自己去 Read）。
- 想拿别的模型做对照实验，用 `--system-prompt <另一份文件>`，不要直接改默认文件。
- 排查「模型到底收到了什么」：

```powershell
& $PY $WS\code\execution\today_new.py prompt --cards-only 1 --stdout
```

## 四、质量自检（由脚本机械执行，不靠模型自检）

| 检查 | 在哪里 | 拦不拦 |
|---|---|---|
| 逐张覆盖（一张不漏、不多） | `check_coverage`（`merge`） | **拦**，不通过不写讲义 |
| `teach` 非空 | `check_coverage` | **拦** |
| 讲义无残留 `{{占位符}}`、词形都出现 | `check_render` | **拦** |
| JSON 合法（含剥围栏/剥前后话的抢救） | `extract_json` | 失败则带提示重问 |
| 例句用上目标词 | `check_examples` + `gen` 返工 | 先自动**重问**，最终仍不合格只**报告** |
| 截断 / 漏卡 | `gen_one_request` | 按卡降级重问 |

> 口径沿用全工作区的原则：**同一件事只查一次，且查在"改库前"**。
> 讲义这条链路从不写 Anki，所以"改库前"就是"写讲义前"。
