`gen_i1_prompt.py` 用你 Anki 里的**真实复习数据**拼出一段提示词，把它丢给任意语言模型
（Claude / GPT / Gemini / 本地模型），出来的就是一篇「i+1 可理解输入」的日语短文。

它回答两个问题，答案全部来自你的收藏：

| 问题 | 数据来源 | 状态 |
|---|---|---|
| 我**已经会**哪些词？ | 词汇 deck 里 `-is:new` 的卡（type=1/2/3，排除 suspended/buried） | 仍成立 |
| 我**接下来几天会学到**哪些词？ | ~~按各 deck 的**真实新卡顺序**，往后推 `天数 × 每日新卡上限`~~ | **已失效，见上方警告** |

## 一、最常用的三条命令

```powershell
$PY = "python"
$WS = "<工作区根>"

# 1. 看库里的存货与「学习前沿」（不生成提示词，最常用）
& $PY "$WS\archive\experiments\gen_i1_prompt\gen_i1_prompt.py" --stats

# 2. 日常用法：未来 7 天、12 个目标词，随机挑一个主题
& $PY "$WS\archive\experiments\gen_i1_prompt\gen_i1_prompt.py"

# 3. 指定主题
& $PY "$WS\archive\experiments\gen_i1_prompt\gen_i1_prompt.py" --topic "在便利店打工的第一天" --targets 8 --days 3
```

生成后：

- 提示词在 `out\i1\prompt_<时间>_<主题>.md`，`out\i1\latest.md` 是最近一份的副本
- 本次的机器可读输入在 `out\i1\manifest_<时间>_<主题>.json`（已知词数、目标词明细、各 deck 学习前沿）

**把 `latest.md` 整个复制粘贴给语言模型即可**，不需要再补充说明。

## 二、关键参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--days N` | 7 | 往后看几天的新卡 |
| `--per-day N` | 见下 | 每天学多少张新卡。不给就读配置区的 `DECK_LIMIT_SOURCE` |
| `--targets N` | 12 | **想要**的目标词个数。受下面两条约束，实际通常收下 6–8 个 |
| `--max-chars N` | 650 | 自动篇幅模式下的字数上限 |
| `--topic "…"` | 随机 | 指定主题 |
| `--count N` | 1 | 一次生成 N 份不同主题的提示词 |
| `--focus` | 关 | 不按 N3/N2 配额，纯粹取「学习顺序最靠前」的词 |
| `--decks "…"` | 全部 | 只用指定 deck（支持前缀匹配，逗号分隔） |
| `--known-cap N` | 分级 | 已知词表每级最多列几个词 |
| `--length "350–450 字"` | 自动 | 指定篇幅。给了就不自动推算，生词率可能被推高，提示词里会带警告 |
| `--style "…"` | 普通体 | 语体要求 |
| `--refresh` | 关 | 忽略本地缓存，重新拉 Anki |
| `--stdout` | 关 | 只打到屏幕，不写文件 |

### 三条约束互相牵制（重要）

「短文长度」「目标词个数」「每个词出现几次」不能同时满足，脚本的取舍顺序是：

```
先框住篇幅（--max-chars，默认 650 字）
  → 每个生词至少出现 2 次（只出现 1 次记不住）
    → 生词 token 占比 ≈ 4%
      → 最后才决定能收下几个词
```

所以 `--targets 20` 实际只会收下 7 个，并在提示词里注明「剩下 13 个留给下一次」。
想要更多词，就放宽篇幅：`--max-chars 1200`。
日语粗略按 `1 字 ≈ 0.61 个词`（分词后）估，650 字 ≈ 400 词。

## 三、「已掌握」和「接下来几天」是怎么算出来的

### 3.1 已掌握

对配置区 `VOCAB_DECKS` 里的每个词汇 deck，抓 `deck:"…" -is:new` 的笔记。
这些卡已经脱离新卡队列（learning / review / relearning），就是「学过」的定义。
`is:suspended` 的卡不算，因为它们没在复习。

实测这份收藏：**3009 个词形**（去重后），分布 N5 736 / N4 730 / N3 375 / N2 210 / N1 3 / Core6000 955。

### 3.2 学习前沿（frontier）

每个 deck 的学习顺序不一样，脚本按 deck 类型分两种方式取值：

- **考级词汇系列**：顺序 = 卡在 Anki 新卡队列里的**位置**（`cardsInfo` 的 `due` 字段，新卡时它就等于位置）。
  学习前沿 = 所有已学卡位置的最大值。实测 N2 高频 deck 的前沿是 225。
- **Core6000**：顺序 = 笔记里的 **`Index` 字段**（就是词频序）。实测已学 `Index` 1–4856，
  所以「下一个要学」是 `Index` 4857。

> **为什么不能简单排序**：你的 deck 选项组里 `new.order = 1`（随机顺序），
> 所以「下一个词」不能靠 deck 内顺序推，必须读卡的真实位置。

### 3.3 接下来几天的新词

`取位置 > 前沿 的新卡，按位置升序，取前 (每日新卡上限 × 天数) 个`。

这就是「你接下来会遇到的词」——包括你跳着学、漏在前面的那些词也不会被误当成「接下来」。

### 3.4 每天新卡上限（容易搞错的地方）

Anki 的 `new.perDay` 是**按选项组**算的。

> ⚠ **这一节的前提已经变了**：考级词汇**扁平化**了 —— 原先 11 个按级别/频段切分的
> 子 deck 合并成「2-考级词汇」一层，子 deck 与父 deck 处在不同选项组、上限不同的坑
> 随之消失。现在学习单元就是 deck 本身，脚本直接读它的 `deckConfig`
> （`DECK_LIMIT_TREE` / `DECK_LIMIT_SOURCE` 已清空，只有 deckConfig 读不到时才用兜底值）。
> 级别与频段改由 eggrolls 笔记标签区分（`eggrolls-JLPT10k-v3.5::4-N2::N2高频`，
> 见 `code/common/jp_decks.py`），`VOCAB_DECKS` 里的 11 条因此是
> 「同一个 deck + 不同 tag」。

当前实测（`--stats` 会打印每个单元的上限**来源**，方便核对）：

| deck | 选项组 | 上限 |
|---|---|---|
| `2-考级词汇`（含全部 11 个级别/频段） | 单词（JLPT） | **10/天** |
| `1-高频日语单词 6000` | 单词（Core 6000） | **10/天** |

注意 11 个级别单元各自读同一个 deckConfig，所以 `--stats` 里每一行都显示 10/天 ——
那是**单元**的上限口径，考级词汇全体的实际速度仍是 10/天，不是 110。

## 四、目标词是怎么挑的

不是简单取「位置最靠前的 N 个」。脚本按 band 分配名额：

| band | 权重 | 依据 |
|---|---|---|
| N3 | 50 | 高频 N3 的 381 张已学完，正在推 N3 低频 |
| N2 | 35 | 刚开始（210 词），是接下来的主战场 |
| Core6000 | 15 | 当词频补充 |
| N1 | 10 | 只学了 3 个，纯补充 |

几个刻意的设计：

- **片假名外来语降级**：`ダウン`、`スマート`、`ブーツ` 对中文母语者不算真正的生词，
  放进「最后才用」的池子，只在名额凑不满时才用。
- **同一个词形只出现一次**：实测「身近」同时在 N3 高频和 N2 高频两个 deck 里，
  按 band 优先级先到先得，避免配额被重复词虚占。
- **每个目标词带出现次数配额**（各 2 次，预算有余时升到 3 次），让生词铺满全文而不是挤在一段。

## 五、提示词里包含什么

生成的提示词有 7 个部分，全部由脚本拼装（没有 LLM 参与）：

1. **学习者画像** —— 母语、已知词量、水平定位、语法进度
2. **已掌握词表** —— 按级别列出，N5/N4 只列少量示意（默认全部会的），N3/N2/N1/Core 列已学的
3. **目标词** —— 通常是 6–8 个词，带读音 / 词性 / 中文释义 / 级别 / 出现次数配额
4. **难度约束** —— 篇幅、生词率、只许用 N5–N3 句型、句长、汉字注音规则、语体
5. **内容** —— 主题 + 场景要求
6. **输出格式** —— ①短文 ②全文翻译 ③逐句对照 ④目标词讲解 ⑤语法点 ⑥自测 ⑦覆盖率自评
7. **反例** —— 明确禁止的写法

第 ⑦ 节要求模型自查「是否有超出已知集合的其他生词」，有就回去改——这一步是生词率可控的关键。

## 六、缓存

`data/i1/gen_i1_cache.json` 存各 deck 的新卡位置（按卡 ID）。

**新卡的位置在 Anki 里永不改变**，所以缓存只需追加、不会失效，第二次以后跑得很快
（首次约 10 秒，之后同样量级）。用 `--refresh` 强制重建，`--no-cache` 完全不读写缓存。

## 七、要改配置时改哪里

脚本顶部 `CFG` 区，都在文件开头：

| 配置 | 什么时候改 |
|---|---|
| `VOCAB_DECKS` | 新增/改名词汇 deck，或改 `band` 分层 |
| `BAND_WEIGHT` | 想把额度挪到别的级别（比如 N2 学完了、改推 N1） |
| `DECK_LIMIT_SOURCE` / `DECK_LIMIT_TREE` | 改了 Anki 里的每日新卡上限 |
| `FIELD_ALIASES` | 新 deck 的字段名不一样 |
| `DEFAULT_TOPICS` | 想换主题池 |
| `LEVEL_CAP` / `LEVEL_NOTE` | 已知词表列多长 |
| `CORE_PREFER_KANA_FALLBACK` | 要不要把片假名外来语降级（默认降） |

篇幅与生词率相关的量在 `build_prompt` 里：`want_ratio`（默认 4%）、`base`（每词出现次数，默认 2）、
`--max-chars`（默认 650）。

字段名不确定就先看 `--stats` 报的错（它会打印该 deck 的实际字段列表），
或者用 `_probe_i1.py` 那类一次性脚本探一下。

## 八、已知边界

- **只覆盖词汇 deck**：语法句型没有参与「已掌握」判定，提示词里的语法约束是**写死的规则**
  （「只用 N5–N3 句型」），不是从语法 deck 的真实进度推出来的。
  想让它也吃语法进度，可以照 `VOCAB_DECKS` 的路子加语法 deck —— 目前没做。
- **汉字级别不细分**：提示词里「N2/N1 级别的汉字要注音」是交给模型判断的，
  脚本没有汉字→级别的表。
- **「已掌握」= 卡片脱离新卡队列**，不代表真的记住。要更严可以按间隔过滤（如只算间隔 ≥21 天的）。
- **不加卡、不改库**：这个脚本只读 Anki。生成的短文如果要进 Anki，是另一步。

## 九、自检

`test_i1_prompt.py` 是回归自检（不连 Anki，用合成数据）：

```powershell
& $PY "$WS\archive\experiments\gen_i1_prompt\test_i1_prompt.py"
```

它检查三件事：

1. 用 AST 扫脚本有没有「读取了未定义的名字」这类拼写错误
2. 压测 `choose_targets` 的配额算术：count=0/1/2/99、空池、只有 skip band、Core 全是片假名、focus 模式
3. `build_prompt` 在各种词数（0/1/2/5/8/12/30）× 篇幅模式下不崩，且配额行数与实际词数自洽

> 这个自检曾经抓到过一个真 bug：当所有候选都落在 `band='skip'` 的 deck 里时，
> 配额算术里 `sum(quota)` 恒为 0，`while sum(quota) < count` 会**死循环**。
> 现在 `active` 为空会提前返回，两个 while 也加了 `guard` 上限。

改完脚本后建议跑一遍。
